# Agent Workforce Lab · UI 设计系统

> 2026-10-29 · 产品实现规范；用于约束当前 React 产品及后续页面。

## 2026-10-30 选定方向：员工端 C · 成长路线

员工端以“资料 → 澄清 → 方法 → 考试 → 印记”为主要空间结构。首页展示当前能力所在关口、未能接任务的原因和唯一下一步；学习页将同一条路线与当前操作并排。五个关口必须由真实领域状态驱动，不使用假进度。

- 中文系统无衬线；页面标题 24–26px，禁止超大宋体与营销 Hero。
- 员工端采用低调蓝灰工作台：`#285DC5` 主动作、`#202B39` 主文案、`#F5F7FA` 页面底、`#FFFFFF` 内容面、`#DCE3EC` 边线。
- 绿色仅表示完成，暖色表示需要真人处理；状态同时写出文字。
- 首页负责理解全局，学习页负责完成动作，成长档案负责核查证据。
- 移动端按“身份 → 路线 → 当前动作 → 已获印记”纵向排列；成功提示不得遮挡顶部导航。
- 运营端是独立产品入口，继续使用任务现场，不把发布、考核和验收混入员工端。
- 首次使用页先展示“专家阶数字分身图鉴”：用印记、验收战绩、组队履历和证据可回查呈现成长终局。它是产品等级图鉴，不使用“虚构、样例数据、不是你的数据”等研发免责声明，也不把图鉴冒充当前账号档案。
- 视觉高光只用于专家分身与能力印记。采用深蓝能力殿堂、金属印记和轻微辉光；不采用全屏 HUD、持续闪烁、跑马灯或无证据的战力数值。
- 首次使用页必须形成完整纵向叙事：专家终局 → 四级成长图鉴 → 获得的工作权限 → 创建分身。桌面长页面不得只放一张首屏卡后留下大面积空白。

## 当前设计方向：围绕员工成长与任务交付的产品工作台（v4）

当前正式产品不再按后端领域模块组织首页。用户进入后先看到需要自己决定什么、数字员工正在做什么、每位员工下一步要跨过什么门槛；学习、验证、治理等模块作为完成这些目标的工作区存在。

正式入口：React 应用 `frontend/src/main.tsx`。`design/prototype/` 下的广场与校园仅作为历史交互研究，不再指导产品信息架构。

- 一级工作区：今日工作台、经验学习、数字员工、能力验证、任务作战室、信任中心。命名使用用户目标，不使用后端模块名。
- 首页只呈现三类可操作对象：必须由真人决定的例外、正在流转的真实任务、数字员工下一道成长门槛。流程说明默认收起。
- 统计数字必须能进入对应工作对象；没有下钻行动的指标不得占据首屏。
- 数字员工详情是“成长档案”，先说明从谁身上学习、已经吸收什么、当前能承担什么，再展示能力证据、明确禁区与真实工作履历。
- 每个成长状态必须给出下一步行动；待试岗进入能力验证，已有印记进入真实任务积累，不使用泛化的“管理”“配置”动作。
- 任务页用成员卡、加入理由、工作记录和真人结果直观表达独立执行、双人协作和三人成组，不依赖人物移动动画。
- 所有状态由真实 API 和 SQLite 数据驱动；不显示预置成功，不用知识数量冒充能力。
- 任务发布后直接展示员工的资格判断：能否独立承担、能力依据、缺口、禁区、负载与建议协作者；用户确认启用，引擎负责最终门禁。
- 没有单人覆盖全部能力时，紧接候选判断展示最小团队方案；卡片写清每位成员负责什么。两人显示协作，三人及以上明确显示将建立任务组。
- 执行中不提供“手工找人”作为主路径。员工先报告能力缺口，系统展示合格帮手、补齐能力、负载、匹配分和加入后的组织变化；真人只确认关键成员变更。
- 求助是任务时间线里的高优先级事件：待处理时使用暖色事件区；确认后事件区退出，协作现场从一人／两人平滑更新为新成员或任务组，原任务和工作记录不重置。
- 工作记录与正式成果使用不同视觉层级。正式成果区固定展示当前版本、历史版本、证据数量、真实动作、独立评审分数与逐项门禁；历史版本只读保留。
- 评审使用文字加颜色表达“通过／未通过”，真人验收按钮只在当前版本通过独立评审后出现。退回不是覆盖原内容，而是引导提交下一版本并填写修改说明。
- “任务匹配分”只是规则排序指标，不表述为模型置信概率；是否可接单始终由资格、授权、风险和任务版本硬校验。
- 视觉采用深松绿导航、暖灰工作底、白色内容面和克制的状态色。装饰服从证据、边界与操作效率。
- 动效仅用于操作反馈、成员加入和状态变化；支持减少动态效果。
- 六个一级工作区使用 `/learning`、`/workers`、`/trials`、`/tasks`、`/governance`
  等真实 URL，支持刷新恢复、分享和浏览器返回。下一步再为员工、案例和任务详情
  增加对象级 URL。
- 权限必须改变用户的操作面，而不只显示角色名称：普通成员保留证据阅读能力，
  不展示连接、同步、导入与撤权；管理员管理来源连接；负责人承担成员管理和撤权。
  服务端 403 是安全边界，前端渐进披露用于减少误操作。

## 历史设计方向：数字员工工作室（v1）

面向知识贡献者与内部项目负责人的桌面 Web。使用简洁网格、清晰的信息层级与可核查的证据；协作现场有空间感，但不以小镇动画取代工作成果。浅色界面、深蓝侧栏、青绿色主动作，暖灰背景降低长时间阅读负担。

## 技能使用与适配记录

已使用 `ui-ux-pro-max` 的 `--design-system`，查询 `enterprise knowledge workforce dashboard`，再以 `operations dashboard` 收窄重试。

- 已核验匹配：Minimalism & Swiss Style 适用于 enterprise apps / dashboards；清晰层级、少装饰、文字状态、焦点、减少动态效果。
- 未采用：两次推荐的营销 Hero / CTA / Conversion 页面模式均不匹配任务工作空间。没有已验证的页面模式匹配，信息架构采用 PRD 驱动的设计判断，不将其伪装为数据库匹配。
- 青绿、暖灰、深蓝组合是产品设计调整，不是技能原始配色的照搬。主要前景／背景组合须验证对比度。
- 字体采用本机中文无衬线，不加载第三方字体；英文数字可用系统等宽字体。
- 已查询 `keyboard focus modal --domain ux` 与 `state forms accessibility --stack react`：使用语义按钮、标签、可见焦点，后续 React 表单受控；不因技能推荐而增加框架依赖。
- 2026-10-29 使用 `ui-ux-pro-max` 复核动态求助：采用渐进披露、明确提交反馈、单一主操作和移动端内容优先；未采用技能返回的营销演示页面与推荐外部字体，因为它们不适合企业任务工作台和本地离线约束。
- 2026-10-29 再次使用 `ui-ux-pro-max` 复核产品级结构：保留 Minimalism & Swiss Style 的清晰层级、低装饰和可见焦点；未采用技能返回的 Hero + Features + CTA、AI 紫粉配色与营销字体，因为当前是持续操作的企业工作空间。结构调整以产品蓝图中的“每天为什么打开”为依据：首页从五步流程和指标卡改为待办、工作现场、成长门槛；数字员工页改为成长档案。

## 导航与布局

桌面侧栏 224px，内容最大宽度 1440px，左右内边距 32px。一级导航四组：工作总览、知识与人才、工作与交付、治理。总览提供完整生命周期、一个主要行动、当前协作现场和真人待办。

≥1024px 双栏／三栏；768–1023px 缩窄侧栏、内容双栏；<768px 侧栏变为顶部可折叠导航，主体单栏。375px 不产生整页横向滚动；复杂图使用纵向节点列表。移动端不把八项导航硬塞进底栏。

## 组件与状态

- 卡片：标题、依据、状态、行动；避免可点击容器内嵌按钮。
- 状态：通过／待核分／阻塞／需复核／未接通，同时写文字，不能仅依赖颜色。
- 模式：持续标注“UI 原型 · 样例数据”；SDK、模型显示未接通，不能显示假健康。
- 资格：展示技能、分数、有效条件；积分不表现为资格进度。
- 来源：使用原文引用与位置、确认性质、用途和受众，敏感字段不展示。
- 图谱：节点按钮可打开来源，提供列表切换；不能只靠拖拽、悬浮或颜色读取。
- 弹窗：原生 dialog、明确关闭/Escape、初始焦点、关闭后返回触发点，内容可滚动；删除／撤回需二次确认。
- 表单：可见标签、字段错误、失败保留输入；无后端的提交只演示并明确提示不保存。
- 动效：背景／边线 160ms，非必要动画关闭；不做闪烁状态、自动播放、强制滚动。

## 原型与实现分界

`design/prototype/` 为独立静态 HTML/CSS/JS 设计原型，不是 React 应用。只模拟导航、来源查看、图／列表切换、样例核分、验收与积分、撤回影响；刷新恢复初始样例。无 API、无持久化、无真实身份或权限保证。所有真实门禁依 PRD 在后续后端实现。

UI 评审确认后，再将原型布局转为 React/TypeScript 组件，使用后端契约驱动状态，不复制原型样例逻辑作生产引擎。
