# Agent Workforce Lab · UI 方向探索 v12

本目录由 `product-ui-director` 设计流程产出，仅用于选择产品视觉方向，不修改正式 React 产品。

## 同一产品故事

三套方向都使用同一条故事线：晓禾从真人压测经验中学习，通过试岗后独立接单；执行时发现数据库能力缺口，邀请林峥协作；安澜作为第三名执行者加入后，系统建立“长稳压测攻坚组”；三人共同提交带证据的成果，由真人验收。

## 三个方向

### 01 能力铸造线

- 核心隐喻：经验输入—验证—能力输出的一条铸造线。
- 卖点：第一次看产品的人能快速理解“经验如何变成可工作的能力”。
- 取舍：产品机制最清楚，但工作现场感弱于方向 02。

### 02 工作剧场

- 核心隐喻：数字员工在同一个持续存在的工作空间里学习、接单、求助和成组。
- 卖点：人物与协作变化最有现场感，最适合展示一人、两人、三人成组。
- 取舍：视觉表现最强，但企业治理信息需要进入二级页面。

### 03 人才操作系统

- 核心隐喻：围绕员工能力、证据、边界和放权建立可信人才系统。
- 卖点：最专业克制，适合强调企业采购关心的可信度和治理。
- 取舍：理性、可信，但情感吸引力和故事性弱于方向 02。

## 反模板约束

- 不使用“左侧导航 + 四张 KPI + 卡片网格”作为所有方向的共同骨架。
- 人、能力、任务、证据、成果使用不同的视觉对象，不统一装成卡片。
- 核心视觉只服务于经验转化、能力验证和动态协作。
- 动效只用于阶段变化，不用粒子、进度动画伪装学习或执行。
- 所有“学会”“可接单”“完成”都伴随证据、边界或真人验收。

## 运行

在本目录启动任意静态服务器，打开 `index.html`。URL 支持：

```text
?concept=forge&stage=learn
?concept=theatre&stage=team
?concept=atlas&stage=result
```

`concept` 可选 `forge`、`theatre`、`atlas`；`stage` 可选 `learn`、`trial`、`solo`、`help`、`team`、`result`。
