# Agent Workforce Lab：项目主线

> 状态：第一阶段评审稿，待项目负责人确认。
> 日期：2026-10-23（Asia/Shanghai）
> 当前交付仅为文档，不代表应用、模型或 Semantica 已接通。

## 1. 一句话定义

把员工自愿贡献的简历、工作经历、方法与资料编译成有来源、可授权的知识与能力档案，让数字员工学习、考试、自主组队领取任务，并通过独立评审、真人验收和积分奖励形成持续成长的数字组织。

**核心主线：**

真人授权贡献资料 → 编译知识与能力档案 → 数字员工学习 → 考试验证 → 自主组队领取任务 → 协作交付 → 评审与真人验收 → 积分奖励、能力成长与经验回流。

不是“把简历变成会聊天的头像”，也不是“让多个 Agent 自由聊天”。关键是回答四个问题：

1. 这些知识从哪里来，谁允许它被使用？
2. 数字员工究竟能做什么，如何证明？
3. 它为什么选择这项任务和这些队友？
4. 最后交付了什么，谁验收，奖励是否合理？

## 2. 要解决的业务问题

| 当前问题 | 产品机制 | 应验证的变化 |
| --- | --- | --- |
| 工作经验散落在简历、笔记、项目材料和个人记忆里 | 授权资料采集、结构化访谈、来源定位与知识包 | 能检索到方法及其适用条件，而非只有技能标签 |
| 知道某人做过项目，不等于数字员工会做 | 学习路径、场景考试、证据化能力资格 | 能展示学习前后在同类任务上的可复核差异 |
| 跨团队找人和对齐耗时 | 基于资格、授权和负载的自主组队提案 | 组队理由清晰，缺口显式暴露 |
| Agent 过程热闹但没有结果 | 任务验收标准、产物版本、独立 Critic 和真人验收 | 任务完成必须对应可检查的交付物 |
| 奖励脱离真实贡献，重复结算 | 冻结团队分工、交付证据、一次性奖励账本 | 积分可解释、可审计且不能重复领取 |
| 经验积累后无法复用 | 将验收意见和结果编译为待确认经验 | 后续任务能复用，但不会把失败或推断变成事实 |

首版不预先宣称节省百分比、模型训练收益或“数字员工等同真人”。业务收益必须通过后续真实试点测量。

## 3. 参与者与责任边界

| 参与者 | 主要职责 | 明确不做 |
| --- | --- | --- |
| 真人知识贡献者 | 自愿贡献材料、补充上下文、确认事实、指定使用范围、纠正与撤回 | 不因贡献资料自动承担数字员工的所有输出责任 |
| 能力数字分身 | 表达真人已授权的经历、知识背景和协作偏好，辅助知识发现与匹配 | 不冒充本人，不自动作承诺，不继承全部个人资料权限 |
| 岗位数字员工 | 持有自己的岗位、知识包、考试资格、负载与工作记录，参与组队和交付 | 不因关联某位真人便获得其“能力等级” |
| 独立评审角色 | 根据固定标准检查证据、逻辑、约束与产物质量 | 不评审自己的执行任务，不替真人最终验收 |
| 任务发布者／管理员 | 提交目标、输入、期限、红线、验收标准与积分预算，处理阻塞 | 不能绕过员工授权读取全部个人知识 |
| 真人验收者 | 接受、退回成果或明确终止；对奖励结算提供最终业务确认 | 不把数字员工积分直接记入真人 HR 绩效 |

同一真人可以贡献知识并发布任务，但发布任务不自动扩大资料授权。管理员是组织角色，不是私密资料的默认超级读者。

数字员工可学习来自多位真人的知识包，同一个真人也可以授权多名数字员工使用不同知识；不强制一人对应一个数字员工。

## 4. 贯穿案例：客服问题分析与知识库改进

以下人物、资料、数值均为脱敏演示样例，不是真实员工能力评定。

### 4.1 原始材料

员工“小林”提供：

- 一份简历：描述曾参与客服知识库建设。
- 一份项目复盘：记录问题分类、升级流程和历史改进做法。
- 一份 FAQ 方法说明：描述术语、适用条件和不可对外承诺事项。

资料中出现“参与降低重复工单”的自述。系统必须保留其来源与自述属性，不能自动写成“效果已被验证”，也不能由此宣布数字员工已掌握客服运营。

小林只授权指定数字员工在“内部客服改进”用途下使用复盘与方法；简历中的私人联系方式不进入可共享知识包。

### 4.2 编译和确认

系统提出档案草稿与知识关系：

“项目经历”关联“问题分类方法”，“升级流程”关联“风险条件”，“FAQ 编写规则”关联“质量检查清单”；每条知识关联原文片段和版本。

小林核对贡献角色、时间、方法适用范围和敏感项。通过确认的知识组成版本化知识包；仍有争议的推断保留为待确认，不授予能力资格。

### 4.3 学习与考试

数字员工“分析员 A”申请学习问题分类知识包；“写作员 B”学习 FAQ 方法包。

- 学习前，用保留题评估基线，记录未能识别升级风险的问题。
- 学习时，按任务检索知识、引用来源、练习适用条件。
- 考试时，使用未见过的脱敏案例；允许按明确规则检索已授权方法，但不能读取答案或评分配置。
- 分析员 A 若未通过升级风险题，只能继续学习、补考或与具备资格的同伴组队，不能直接领取要求该资格的职责。

考试输出是“在指定知识包、工具条件和题目版本下通过某项能力考核”，不是“永久拥有所有客服经验”。

### 4.4 任务池与组队

管理员发布：“分析一批脱敏客服问题，交付分类清单、FAQ 改进草稿与风险列表”，附输入数据、验收标准和演示积分预算。

分析员 A 提出负责分类，写作员 B 提出负责 FAQ；双方给出资格证据、可使用知识包与当前负载。系统检查能力覆盖、授权、角色冲突和负载后，原子地确认团队与任务归属。

当无人具备必需资格时，任务显示“能力缺口待补齐”，系统建议学习或补位，不伪装成已成功组队。

### 4.5 交付、退回与验收

团队提交三个版本化产物：分类表、FAQ 草稿、风险列表。每项主要结论关联引用；未知问题明确标注“材料不足”。

独立评审发现 FAQ 包含未经授权的退款承诺，将任务退回。团队按红线修订后重新提交，真人验收者检查结果并接受。

评审通过不等于任务完成；只有真人验收接受、版本与授权均有效时，才能进入结算。

### 4.6 奖励与经验回流

验收触发一次性积分结算。示例预算为 100 积分，示例分工为分析员 A 60、写作员 B 40；该数值仅展示账本机制，不锁定正式 PRD 的奖励规则。

重复点击验收不能再次领取积分。评审角色不参加同一任务的执行分成。

“发现退款承诺越界”的教训进入待确认经验，保留项目、产物和评审来源。它不反向变成“小林犯过此错误”，也不自动改写小林的简历。

### 4.7 撤回演示

小林撤回 FAQ 方法包授权：新检索立即拒绝，尚未完成的相关运行暂停；历史产物和考核记录标记依赖受影响，需重新授权、替换依据或复核。

已经进入外部模型上下文的数据无法靠本地撤回“让模型遗忘”，已导出的文件也不能自动收回。首版禁止自动外发，并在首次启用真实模型前说明数据流向。

## 5. 产品体验主线

这里定义需要表达的信息，不预先决定视觉风格或页面布局。

| 工作区 | 用户需要看见的核心信息 |
| --- | --- |
| 知识贡献与授权 | 提交了什么、哪些字段被提取、给谁使用、用于什么、如何撤回 |
| 知识与能力档案 | 来源事实、推断、本人确认、适用条件、版本、知识关系 |
| 数字员工学习中心 | 已获授权知识包、练习、考试、能力缺口、历史资格 |
| 任务池 | 目标、必需技能、积分预算、验收标准、可认领状态和阻塞原因 |
| 团队协作现场 | 组队理由、分工、任务依赖、检索依据、讨论、决定与运行状态 |
| 交付与验收 | 产物版本、引用、Critic 意见、修订记录、真人接受或退回 |
| 成长与治理 | 积分账本、能力资格、完成记录、审计、暂停与授权失效影响 |

小镇空间可以在 UI 阶段作为观察工作状态的表现形式，但不能替代任务、证据、资格与交付主线。Lamoom 作为个人代理体验参考，不作首版运行依赖。

## 6. Prototype 成功标准

### 6.1 必须可演示的闭环

1. 从一组脱敏资料生成可核查的知识草稿，完成确认与授权。
2. 数字员工学习前后接受可比较评估，展示考试通过与失败两条路径。
3. 任务发布后形成有理由的团队；能力不足或授权不满足时拒绝认领。
4. 输出真实可查看的样例成果，经历至少一次评审退回和修订。
5. 真人验收后奖励到账，重复请求不会重复结算。
6. 撤回授权阻止后续使用，重启后保留任务、考试与账本状态。
7. 演示与真实模式始终可辨；真实模型失败不会被演示答案覆盖。

### 6.2 衡量口径

记录资料编译的来源定位正确率、引用支持率、同条件考试前后结果、任务能力覆盖、一次评审通过率、真人返工次数和模型调用成本。

对比至少包括“未加载知识包”和“加载知识包”的同模型、同工具条件；使用不同但等难度保留题，避免把重复题记忆当成知识迁移。多 Agent 增益再与单 Agent 组做独立比较。

首版只证明机制能运行、结果可追溯，不把少量演示样例外推为组织生产率提升。

## 7. 范围与长期愿景

| 首版内部 Prototype | 后续试点／长期能力 |
| --- | --- |
| 手动贡献脱敏材料、明确授权、本地单工作空间 | 经审批的企业资料连接器、组织身份、用途与字段级治理 |
| 知识图谱与检索增强、考试验证 | 更丰富的经验采集、多领域考核与长期效果校准 |
| 有限数字员工、受控运行、可解释组队 | 多项目调度、跨组织能力发现、资源公平机制 |
| 文档／结构化分析等低风险交付 | 隔离执行工具、真实业务系统集成与更严格验收 |
| 不可兑现金积分、数字员工能力等级 | 资源激励实验；真人激励须另行设计归因和合规 |
| 本地演示角色切换，非生产认证 | 真实认证、组织授权、多租户与安全审查 |

不在首版范围：AS 集成、公网部署、员工电脑自动扫描、复用已有项目凭据、模型微调、任意 Shell 执行、自动外发、真实资金支付或真人 HR 评价。
