# 产品主线修订：从真人教学到数字员工交付

> 日期：2026-10-24。依据项目负责人对主线和首页的明确纠正。
> 本文覆盖旧文档中与之冲突的产品范围与 UX 约束；尚未实施新界面或后端。

## 1. 产品定义与卖点

**把你的经验教给数字员工，让它逐步成为能接任务、找帮手、交付成果的工作伙伴。**

不是先造一个多 Agent 控制台，再往里面导入知识；也不是先造广场，再给角色配上任务。产品起点是“一个真人，持续教一个数字员工”，终点是“用户拿到成果，并且知道它如何完成”。

面向客户的三个价值：

- 经验可传承：不必一次写完知识库，日常讲解、资料、示范与纠正都能持续积累。
- 员工会成长：不会就问，通过考试与简单任务证明能力，而非自称已经学会。
- 工作可托付：自行评估接任务，必要时找其他员工协作，用户直接看进度、阻塞和成果。

底层仍采用授权知识、图谱和检索，不因此宣称模型参数训练或无条件复制真人全部能力。

## 2. 四阶段主线

### 阶段一：真人持续教数字员工

用户创建并命名一个数字员工，指定主要教学者和岗位目标，不要求先填复杂技能表或构建组织。

教学入口包括：

- 讲一段知识、解释一个判断、回答员工提出的问题。
- 提供简历、个人资料、工作材料等有权处理的内容。
- 描述今天完成的一项工作，演示步骤与判断理由。
- 让员工复述理解、尝试应用，并纠正错误。

数字员工主动反馈“我理解了什么、还不懂什么、在哪种情况下需要你帮助”，提出具体澄清问题。问题进入“待我教”清单，真人可以稍后回答。

新知识经过来源、适用条件与授权确认后成为持续记忆。上传资料不等于掌握；复述、练习与验证也要分别可见。不默认监控电脑或抓取日常工作。

### 阶段二：学习、考试与简单任务，取得接任务资格

成长过程为“学习中 → 练习与考试 → 试岗小任务 → 可接对应任务”。资格按技能与条件记录，不是所有知识领域统一毕业。

简单任务有实际成果与真人反馈，属于试岗，不混同正式公开任务；教学者可指导试岗过程。数字员工需要证明能应用知识，而不只是回答选择题。

未通过时解释具体不足、请求教学或补练。已具备某技能接单资格的员工仍可继续学习其他知识、向真人提问。

### 阶段三：真实用户发布任务

发布者可以不是知识贡献者。发布从自然表达开始：“帮我完成什么、希望得到什么成果、什么时候需要”，允许附资料；系统帮助补齐验收条件与限制。

首屏不要求用户理解 DAG、知识图谱、Agent 角色和权重。必要限制逐步披露，发布前让用户确认任务摘要、资料处理范围和奖励预算。

已有很多员工时，用户仍以目标和成果为中心，不必先挑所有成员。

### 阶段四：自主评估、执行与中途求助

员工根据自己的知识、验证能力、可用性和权限判断：

1. 我可以独立完成：提出依据，认领并执行。
2. 需要别人一起完成：寻找互补员工、提出邀请与分工。
3. 暂时没人能完成：说明缺口，向真人请求补充知识或澄清，不伪造团队。

执行中发现新问题时，可以向真人问具体问题，也可以寻找其他数字员工并中途邀请。已有成果、讨论与任务 ID 保持连续，不取消任务再复制。

**按用户规则：1 人为独立任务；2 人为双人协作；第 3 名执行成员加入时，创建任务组并关联原任务。**独立 Critic 与真人验收者不计入执行成员人数。

任务组拥有名称、原任务关联、负责人、成员职责、加入时间、工作项与共享上下文。新成员只收到其职责所需且获准使用的上下文；入组不自动扩大资料授权。

用户看到每次变化的原因：“为什么需要帮手、谁加入、负责什么、对进度有什么影响”。奖励和贡献记录须随实际分工版本变化设计，不能直接沿用冻结团队的旧算法。

## 3. 首页的三个核心功能

首页是用户行动入口，不是指标看板，也不以广场占满屏幕作为默认目标。

| 核心功能 | 默认呈现 | 主要动作 | 进入后用户得到什么 |
| --- | --- | --- | --- |
| 教我的数字员工 | 我的员工、当前学习主题、它向我提出的具体问题 | 教它新知识／回答问题 | 连续教学对话、资料、理解确认、练习与成长 |
| 发布任务 | 一句话任务输入、成果提示、可附资料 | 发布一个任务 | 可确认的任务目标、验收要求与接单评估 |
| 看任务进度与结果 | 我的任务、当前负责人／任务组、正在做什么、阻塞与最新成果 | 看进度／打开成果 | 任务工作现场、成员变化、产物和验收 |

没有员工时，第一项引导“创建我的数字员工”；没有任务时，第二项提供可编辑的任务例子；有员工提问或任务阻塞时，把需要真人响应的事项明确放在对应入口。

### 教学页

真人与数字员工的双向教学是视觉主角。对话旁呈现学到的知识、待确认理解、技能成长与来源，而不是让用户先操作图谱节点。

“员工向我学习”应显示具体问题，例如：“退款例外情况如何判断？我还没有足够依据。”真人回答后能看到员工复述、知识更新和待练习事项。

### 任务页

默认展示当前状态、下一步、阻塞、责任人与最新成果。成果可直接打开；进度采用已完成工作项与里程碑，不伪造线性百分比。

工作现场可切换：

- 工作记录：清楚展示动作、决策、邀请、加入、分工和产物。
- 广场／空间：直观看到员工独立工作、邀请帮手与形成任务组。

广场是任务观察工具，不是替代教学和发布的产品主线。人物移动不能成为理解进度的唯一方式。

## 4. 一条完整的客户演示故事

1. 小林创建“晓禾”，先告诉它自己负责什么，再教一段客服判断经验并上传工作资料。
2. 晓禾复述理解，主动问“什么情况需要升级给真人”；小林补充，它记录方法与限制。
3. 晓禾通过场景考试，完成一个试岗小任务，成果经检查后获得对应技能的接单资格。
4. 另一位用户发布“整理客服反馈并提出知识库改进建议”，晓禾评估可以先独立开始。
5. 执行时发现需要问题分析能力，邀请知远加入，界面变为双人协作。
6. 又发现需要某项专业知识，邀请第 3 名执行员工；系统创建任务组，保留原任务，展示新职责与共享依据。
7. 用户在任务页看到进展、加入理由和当前成果；最终检查交付并验收，奖励按确认后的贡献规则结算。

前两步必须有真实可操作的教学 UX；不能从一批预置合格员工直接跳到广场播放。

## 5. 覆盖的旧约束与待更新内容

- 覆盖旧 PRD “已认领后不换执行成员／中途加人须取消并复制任务”：改为连续任务中的受控加入与任务组升级。
- 覆盖“固定客服三个工作项等同整个产品”：客服仅为演示案例，用户目标与成果是发布入口。
- 补齐旧学习路径缺少的持续双向教学、主动提问和试岗小任务。
- 覆盖 UI v2 “广场作为推荐首页”：首页为三项核心功能，广场进入任务工作现场。
- 原 PRD 中固定分工奖励、资格成长规则、接口和状态机需要随本主线重新整理；不能直接依旧文档开始编码。
- 保留来源、用途、最小权限、考试真实性、独立评审、真人验收、模型模式诚实与独立目录约束。

接下来先基于本主线修订 PRD 与信息架构，再制作完整教学、发布、进度／结果和中途拉人原型。仍在产品与 UI 阶段，不开始业务编码。
