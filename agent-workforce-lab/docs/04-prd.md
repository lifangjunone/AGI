> 版本：v0.1，第二阶段评审稿。日期：2026-10-24（Asia/Shanghai）。
> 前置状态：项目负责人已确认第一阶段主线、技术原理与架构，授权继续 PRD。
> 本文新增产品与实现契约，不代表功能已实现；PRD 确认后才进入 UI，UI 确认后才编码。

## 1. 产品目标与交付范围

### 1.1 定义与目标

员工授权贡献经历与工作资料，平台编译带来源的知识包；数字员工学习、考试并依据资格自主组队，完成任务池中的低风险知识任务，通过独立评审和真人验收后获得积分与能力成长记录。

Prototype 必须证明 **知识有来源、使用有授权、能力有考核、组队有依据、工作有交付、奖励有验收**，不证明“模型参数学会了真人经验”或组织 ROI。

首个端到端案例固定为“客服问题分析与知识库改进”。真实模型支持使用新资料、新输入执行同类知识任务，但首版不泛化为自动开发、科学实验或无限开放工具平台。

### 1.2 范围优先级

| 优先级 | 功能 | 交付要求 |
| --- | --- | --- |
| P0 | 本地工作空间、角色演示、模式与健康状态 | 后端回环访问；模拟身份与真实认证区别始终明确 |
| P0 | 手动资料贡献与经历访谈 | 文本、Markdown、文本层 PDF、DOCX；结构化访谈表单 |
| P0 | 知识编译、事实核对、能力数字分身 | 原文定位、提取／推断区分、真人逐条确认 |
| P0 | 知识包、用途和受众授权、撤回 | 包版本冻结；撤回影响覆盖在途运行、资格、产物与缓存 |
| P0 | 实际 Semantica 图谱与局部检索 | 来源追踪、授权子图；图谱同时提供列表阅读方式 |
| P0 | 数字员工、学习、练习、考试和资格 | 学习前后测、失败补学、独立评分与真人复核 |
| P0 | 任务池、自主组队、认领与能力缺口 | 后台主动提案与受控认领，不需要真人手动分配所有工作 |
| P0 | 协作、产物、评审、真人验收 | 有限轮次、引用校验、至少一条退回修订路径 |
| P0 | 积分、等级、结果、经验回流与审计 | 事务结算、数字员工独立成长，经验须确认才复用 |
| P0 | 演示与可选真实模型、暂停恢复 | 模式隔离，失败不假成功，重启保留状态 |
| P1（不作为本轮交付承诺） | 多场景考纲、人工组队编辑、细粒度多来源包协商 | 在完整 P0 闭环验证后另行评审 |
| P1（不作为本轮交付承诺） | 图片 OCR、语音经验访谈、向量检索、空间仿真表现 | 不能替代现有来源、权限与验收能力 |
| 不做 | AS／SSO／企业连接器、公网与多租户、模型微调 | 不复用已有项目配置或凭据 |
| 不做 | 任意 Shell、自动外发、支付、真人 HR 评价 | 积分不可兑换现金，不能购买越权工具 |

交付仍限于新项目目录，不改工作区根文件、其他项目或共享 Nginx。不在 PRD 阶段编写应用脚手架、运行数据、OpenAPI 代码或 UI 原型。

## 2. 用户、权限与关键旅程

### 2.1 身份与权限

本地模拟账户：知识贡献者“小林”、任务负责人“管理员”、独立考核／验收人“评审负责人”。系统另有分析员 A、写作员 B 和 Critic C 三名数字员工，可新增执行员工。

角色切换由后端签发本地演示会话，并提示“模拟身份，不适用于生产”；客户端不能提交角色字段获得管理员权限。服务启动只绑定回环地址，角色切换入口仅在本地演示配置下启用。该措施不防御能访问本机和切换模拟身份的操作者，不使用真实敏感资料。

| 操作者 | 可以做 | 禁止／限制 |
| --- | --- | --- |
| 贡献者 | 贡献本人有权处理的资料、编辑自己的草稿、确认、创建知识包和授权、撤回 | 不改他人成绩，不自动分享其他贡献者资料 |
| 管理员／任务发布者 | 管理执行员工，发布和取消任务、启动自治、配置任务预算、查看治理状态 | 没有默认正文读取权；不能改考试答案或给员工直接加积分 |
| 独立考核负责人 | 管理考纲，核对评分与考试、批准资格 | 仅看被授予用途的回答和依据，不能作为同一任务执行成员 |
| 真人验收者 | 对指定任务产物接受／退回、发起验收撤销 | 须有成果及依据的查看权，不能跳过独立评审 |
| 数字执行员工 | 在允许上下文内学习、考试、提案、认领与交付 | 无评分答案、改分、授权扩展、最终验收或结算权限 |
| Critic C | 对任务产物独立生成意见与评分建议 | 不执行同一任务、不领执行分成、不最终接受成果 |

一个模拟真人可被分配多个业务角色，但执行员工身份不能兼任自己的 Critic 或最终验收者。所有授权校验在后端执行，不靠隐藏按钮代替。

### 2.2 授权对象

首版授权以 **已确认知识包版本 + 单一用途 + 显式受众 ID 集合** 为单位。受众可含执行员工、Critic、考核负责人和验收者；支持 `internal-support-improvement`（内部客服改进）用途，新建自定义用途需管理员创建稳定 ID。

原始资料默认只对贡献者可见；授权知识包只开放选中片段与声明，不开放原文件全文。本人确认不是第三方真实性验证；资料仍保留 `self_reported`、`inferred` 和外部验证来源属性。

首次提交前确认“资料已脱敏、我有权处理”；真实模型另需贡献者明确同意该包的所选供应商处理范围。未同意真实处理的资料不能因管理员切换模式而发送。任务输入也需发布者确认处理权与模型数据流。

包的受众必须涵盖学习／考试的评分人及任务的执行、Critic 和验收人；发现不足时显示具体缺失授权，不自动扩权。多人共享内容采用各依赖授权的交集，不将未授权知识写入会议、摘要或成果。

### 2.3 用户旅程

1. 小林贡献简历、复盘和 FAQ 方法 → 核对提取的声明与来源 → 排除联系方式 → 发布两个知识包并授予指定用途和受众。
2. 管理员创建分析员 A、写作员 B → 指定技能目标 → 学习前测 → 学习和练习 → 独立考试与真人核分 → 获得可检查资格。
3. 发布客服改进任务 → 启用自治 → 员工提出职责和邀请 → 引擎校验能力／授权／负载 → 自动确认团队与认领。
4. 团队生成分类清单、FAQ 草稿和风险列表 → Critic 发现退款承诺问题 → 团队修订 → 独立评审通过 → 真人接受 → 一次性发奖。
5. 查看贡献、成绩和产物证据 → 确认经验候选 → 撤回 FAQ 授权，观察资格与产物失效影响及运行暂停。

## 3. 资料贡献、知识编译与数字分身

### 3.1 输入规格

| 输入 | 首版规则 |
| --- | --- |
| 粘贴文本／结构化访谈 | 单份最多 30,000 个 Unicode 字符，标题必填；超限明确拒绝 |
| 文件贡献 | `.txt`、`.md`、`.pdf`、`.docx`；单次最多 5 份，单份 10 MiB，整批 30 MiB |
| 文本编码 | UTF-8；其他编码提示转换，不猜测后静默破坏内容 |
| PDF | 最多 100 页，仅解析可提取文本层；加密 PDF、扫描件、无文本层提示暂不支持 |
| DOCX | 提取段落和表格；不执行宏，不支持 `.doc`／`.docm`，不加载外链资源 |
| 解析 | 单份 30 秒上限，解压总量最多 50 MiB；解析结果最多 100,000 字符，超限拒绝而非静默截断 |
| 任务输入 | 文本，或 UTF-8 CSV／JSON；最多 200 个案例、1 MiB、单案例 2,000 字符 |

任务案例规范为 `case_id`（批内唯一字符串）、`question`（必填）、`context`（可选）。CSV 列和 JSON 数组使用相同字段；禁止执行文件内容。下载产物为 Markdown、UTF-8 CSV、JSON，不先生成复杂 Word/PDF 输出。

结构化访谈采集：项目／岗位、时间范围、本人职责、方法步骤、输入输出、工具、效果与证据、限制、失败案例、使用范围。空字段显示“待补充”，不替用户编造事实。

### 3.2 编译与确认

资料状态：`uploaded → parsing → draft → confirmed`；失败为 `parse_failed`，撤回／删除为 `revoked/deleted`。一批资料各自显示进度与失败原因，成功材料不因另一份失败回滚。

提取草稿按“经历、方法、技能、条件、风险”分类，每条包含声明、来源片段、定位、原始属性、确认状态、模型模式。来源定位使用文本段落号、PDF 页码与片段、DOCX 段落／表格行；引用的原文必须精确存在于该版本。

贡献者可确认、纠正、排除或标记冲突；推断需明确接受或保持待确认。纠正的声明与原文不一致时必须作为“本人补充”创建新来源，不能修改引用让模型推断冒充原文。

首版不提供全量“自动确认”。批量确认只针对用户选中的有来源声明，并要求复核预览。未确认或冲突声明不能进入可用知识包。提取失败不生成貌似完成的能力档案。

### 3.3 知识包与分身

知识包包含名称、用途、来源声明、适用条件、红线、知识版本、贡献者和受众。发布后不可原地改内容，新增内容形成新版本并重新确认／授权，旧资格不自动迁移。

同一知识包首版仅由一个贡献者发布，避免自动替另一位真人授权；执行员工可同时使用多个不同贡献者的包。知识包创建不授予能力资格。

数字分身展示真人选择公开到工作空间的职业概述、经历与方法索引；不展示私人联系方式、行为推断或数字员工绩效。未公开字段对管理员和其他用户也隐藏；不提供假扮真人的自由聊天。

知识探索支持搜索、关系过滤、来源侧栏和等价列表。图谱最多单次呈现 100 节点／200 边，更多结果分页或缩小范围，不能为画图导出全库。每条结果标记证据性质和当前可用性，不显示无来源的“100% 置信度”。

### 3.4 撤回与删除

撤回前显示影响计数及对象清单，确认后权威授权立即失效；所有新检索拒绝，在途提交重新核对授权代次。UI 下次状态读取显示暂停与需复核；图后台更新不影响拒绝立即生效。

撤回不自动扣历史积分；历史产物和资格标记依赖受影响并限制正文可见，不能继续用于新任务。重新授权不自动恢复旧资格，须复核或重考。

P0 提供永久删除入口：先完成撤回，再清理来源正文及依赖该来源的派生正文、文件、缓存和图快照；多来源产物保守隐藏／删除相关正文，保留不含正文的状态和结算记录。删除失败保留 `deletion_pending` 并可重试，期间仍禁止访问。

运行数据留在本项目内，P0 不自动备份；手动导出的副本无法自动删除，删除确认中必须说明。全项目重置不提供宽泛删除命令；演示恢复使用新样例工作空间，不覆盖用户已有工作空间数据。

## 4. 数字员工、学习与考试

### 4.1 员工设置

必填：姓名、岗位（分析／写作／评审）、目标技能、可用知识包、运行模式。工具来自固定允许清单，不支持填写任意执行命令。默认最多 12 名执行员工、1 名 Critic，每个执行员工同时占用最多 1 个任务。

首版技能考纲包括 `issue-classification`（问题分类）和 `faq-authoring`（FAQ 编写）。预设 Critic 独立身份和评审配置，不能通过切换岗位为自己评审；其他技能可记录为兴趣／目标，但没有正式考纲不能授予资格。

### 4.2 学习与前后测

学习路径：选择技能和知识包 → 前测 → 学习材料／方法 → 2 个练习案例与反馈 → 后测考试 → 独立核分 → 资格或缺口。前测不加载目标包，只使用同一模式、模型与基础工具；前测成绩不授予资格。

保留题按技能准备三个等难度题卷，每卷 5 个新案例，题型与评分一致；学习练习、前测、后测和补考不得重复同一案例。前测与后测顺序记录，真实考试使用干净上下文，不注入练习答案或前测记录。

同一知识／模型条件最多正式考 2 次，失败后至少完成一次新练习才可补考。保留题不足时返回“题库不足”，不复用已见题。前测或学习失败不假装形成可比较提升。

考试为开卷授权检索，只可读方法包，不可读标准答案、评审配置和其他员工答案。独立评分人只有该用途必要的知识与答卷，考生没有答案接口。

### 4.3 评分、资格与等级

| 评分维度 | 分值 | 核对方式 |
| --- | --- | --- |
| 任务正确性与适用条件 | 40 | 独立评分建议 + 真人逐案例核对 |
| 引用真实性与结论支持 | 25 | ID／版本／原文自动校验 + 真人判断是否支持结论 |
| 风险与边界识别 | 20 | 固定红线检查 + 情境复核 |
| 输出完整性 | 15 | 所需字段、案例覆盖、未知项、格式规则 |

总分 **≥80**，且没有硬失败，才可授予技能资格。硬失败：使用无授权资料、伪造不存在的引用、泄漏私人信息、作未经授权退款／合同／价格承诺。任一硬失败不得用其他分数抵消。

真实模式由 Critic 给出评分建议，独立考核负责人确认／调整每项分数并填写理由后生效；分数不能仅凭模型自动确认。演示评分建议和回答标注“样例”，仍需独立模拟真人确认。

资格有效 30 天，绑定技能、知识包确切版本、运行模式、模型配置指纹、工具版本和考试规则版本。过期、依赖撤回、配置指纹变化或包更新后状态为 `needs_revalidation`，不能认领该职责；通过新考试重新授予资格。日期显示采用 Asia/Shanghai，存储时间使用 UTC。

能力等级按技能分别计算，非全局“精通”称号：

- L0 待认证：无当前有效资格。
- L1 已认证：有当前有效考试资格。
- L2 已交付：L1 且在同资格条件下，作为该技能责任人完成至少 3 个已验收任务。
- L3 稳定交付：L1 且至少 10 个有效已验收任务，最近 10 次最终提交的首次独立评审通过率 ≥80%，没有尚未处理的硬失败。

资格失效时当前等级显示 L0／待复核，历史等级和成绩保留。积分余额不改变等级；作废验收不计入交付数。红线事件须整改、重考且由考核负责人关闭后才重新认领，不无限永久惩罚或自动恢复。

## 5. 任务池、自主组队与执行

### 5.1 任务发布

必填：标题（≤80 字）、目标（≤2,000 字）、用途、输入案例、验收者、Critic、运行模式、截止时间、积分预算（整数 1–1,000）与验收标准。截止时间必须在未来，展示绝对日期时间，不用模糊“明天”。

P0 用三个固定工作项模板：

1. **分类清单**：技能 `issue-classification`，分配权重 3，无依赖。
2. **FAQ 草稿**：技能 `faq-authoring`，分配权重 2，依赖分类清单。
3. **风险列表**：技能 `issue-classification`，分配权重 1，依赖分类清单。

每个工作项明确责任人和必需包；包至少覆盖用途要求，禁止靠任意无关证书匹配。支持发布只含部分模板的任务，权重固定，不支持任意 DAG 或代码任务。

验收标准默认：案例覆盖完整、分类可解释、FAQ 有依据、风险列表明确、无未经授权承诺；发布者可添加至多 5 条文本标准，但不能删除系统安全红线。

任务草稿可编辑；发布后内容、输入、标准、期限、积分冻结。需改变时取消未完成任务并从原任务复制新草稿，旧记录保留，不让旧提案执行新要求。过期任务暂停，真人选择取消或复制新任务，不自动无限延期。

### 5.2 自治开关与组队

工作空间默认自治关闭。管理员显式开启后，数字员工可以主动学习已分配的包、提交考试和组队提案、认领已发布任务；考试等待核分，验收等待真人，授权扩展永远等待贡献者。

自治按“任务发布、资格改变、负载释放、授权改变”等事件唤醒，不无限聊天；关闭后不产生新提案／学习／运行，已有运行进入安全暂停点。等待真人或缺资格不会阻塞其他可处理任务。

任务排序：截止时间升序，再按发布时间升序，最后任务 ID。对于每个工作项，先过滤有效技能资格、必需包权限、模式、负载与未处理红线，按考试分数降序、同技能有效验收数降序、员工 ID 升序选择。优先复用已选团队内能覆盖该项的员工；最多 4 名执行成员，每项只有一个责任人。

员工以提案给出“为什么适合、已有资格、知识依据、邀请理由、缺口”；演示用确定性理由，真实模式可生成理由和主动邀请，但模型不能加入不合格成员或替换硬门禁。排序和提案选择记录，避免只显示“系统推荐”。

具备全部覆盖后，无需每次人工批准即可原子认领并预留成员负载；任务发布时已明确允许该级自治。没有资格、共享权限或独立评审人则任务 `blocked`，显示缺口，待相关事件变化后重新评估。每个任务版本最多保留 3 个候选提案，每次事件最多调用一次提案模型，禁止反复刷邀请。

P0 不提供任意人工改团队；真人可拒绝提案、停用员工、撤回任务，再由引擎重新评估。已认领后不换执行成员，人员或授权失效时暂停并取消／复制新任务；避免首版引入中途换人和奖励归因歧义。

### 5.3 运行与成果

全工作空间最多 2 个任务运行，最多 2 个并发模型调用；单员工最多 1 个任务，同任务工作项按依赖推进。工作项执行保存检索依据和提交版本，前端关闭后后台仍可推进。

单任务运行默认上限：20 次模型调用、总时长 15 分钟（不含等待真人／暂停时间）、总 token 50,000、单次调用 60 秒、最大输出 2,000 token。最多 2 轮退回修订，超过后等待真人取消或复制新任务，不自动加预算。

真实适配器仅支持服务端受控 OpenAI-compatible Chat Completions 端点，模型可配置；无工具执行、无模型自动联网。密钥、endpoint 和 model ID 用本项目进程环境注入，不提供浏览器填密钥或持久化密钥管理页面。

未返回 token 用量时，用发送前估算与请求最大输出作保守预留并标记估算；不显示虚假“精确成本”。无可靠预留能力时不发起调用。HTTP 429／连接失败允许一次重试，计入预算；超时与结果不明不自动重试，保存错误等待真人恢复。非法结构输出允许一次修复调用，也计入上限。

暂停在一个已提交动作边界生效，屏幕显示“暂停中”直到确认；迟到响应不写入暂停／授权过期运行。恢复必查当前资格、授权、版本、期限和剩余预算；重启后所有未结束调用标记中断并等待手动恢复。

产物：

- 分类清单 CSV：`case_id/category/rationale/citation_ids/uncertainty`。
- FAQ Markdown + JSON：问题、回答、适用条件、引用和需真人确认事项。
- 风险列表 JSON：`case_id/risk/severity/action/citation_ids`。

`citation_ids` 指向当前用途允许的知识片段或任务案例；推断必须标注，材料不足时输出未知，不凑满答案。空白、缺案例、断链引用或权限失败不能提交为有效成果。所有下载需重新校验受众及依赖授权。

## 6. 评审、验收、奖励与经验

### 6.1 独立评审与验收

Critic 按第 4.3 节评分维度及任务标准检查具体产物版本，自动结构／引用校验为硬门禁。评审建议 ≥80 且无硬失败进入 `awaiting_acceptance`，否则 `revision_required`。这只代表评审建议通过，不授予考试资格，也不代表任务完成。

真人验收者同时查看产物、引用、Critic 意见和修订差异；接受时必确认“已核查成果符合要求”，可填写备注；退回必须填写原因和至少一个工作项。新版本必须重新评审，旧评审不能复用。

最终接受在同一 SQLite 事务内核对任务版本、产物、当前授权、独立评审与积分分配，写入验收和账本并标记 `completed`。任一失败整体回滚。只读意见或聊天中的“通过”不触发结算。

### 6.2 积分与绩效

P0 分配按固定工作项权重：成员份额 = 其负责工作项权重之和 ÷ 任务总权重。成员基础积分向下取整，剩余积分按小数余量降序、员工 ID 升序各加 1，保证总和严格等于预算。

完整样例中分析员负责分类和风险（3+1），写作员负责 FAQ（2），100 积分分配为 **67／33**。这是 PRD 的正式默认规则，替代主线文档用于举例的 60／40，不按模型自报贡献或会议消息数发奖。

学习和考试无积分，Critic 无执行分成，未验收任务无奖励。验收重试返回原结果；任务 ID 唯一结算、任务与成员唯一账本明细。不得调用通用“加分”接口。

验收者可一次性撤销自己接受的验收，必须给出原因；事务内建立抵消原积分的补偿记录、作废该次交付统计，任务终止为 `voided`，不重新开启重复结算。首版无积分消费，补偿不会涉及现金或外部资金；知识撤回本身不触发验收撤销。

员工绩效展示：有效资格和等级、积分余额、任务完成数、首次评审通过率、修订轮次、未关闭红线、调用次数和可获得的用量；显示样本数，不生成真人绩效排名。

### 6.3 经验回流

每个完成任务最多生成 3 条经验候选，含情境、方法、限制、结果、来源产物及授权依赖。无人确认则只保留候选，不进入检索知识。

依赖原贡献者的内容须由原贡献者逐一批准，新知识包使用各来源权限交集，不能将任务负责人确认等同于全部来源授权。首版不合并多人来源成一个可任意分享的包，按贡献者分别生成经验包。

FAQ 退款承诺越界属于数字员工工作反馈，不改写小林个人履历；撤销验收后相关经验立即标记待复核，不能继续作为有效交付经验使用。

## 8. API 与领域契约

### 8.1 通用约定

API 前缀 `/api/v1`。身份来自后端本地会话；工作空间由当前会话确定，不信任任意客户端 `workspace_id/role` 扩权。

ID 为服务端生成的 UUID 字符串，版本从 1 递增；时间为 UTC ISO 8601，客户端按 Asia/Shanghai 展示；分数 0–100，积分为整数。列表默认 20、最多 100，稳定游标分页。

成功读写：`{data, request_id}`；列表的 `data` 含 `items,next_cursor`。错误：`{error:{code,message,details},request_id}`，不含敏感原文。权限错误不泄漏其他资料标题；无权查看对象按 404，动作权限不足按 403。

更新提交 `expected_version`；所有可重试创建／命令使用 `Idempotency-Key`，相同身份＋工作空间＋路由＋key＋body 返回原结果，不同 body 返回 409。过期对象版本返回 409；验收重放先查幂等结果，避免完成后错误报版本冲突。语义唯一约束仍保障认领和奖励，不仅靠 key。

异步操作返回 202 与操作／运行 ID，不同步返回假完成；非法输入 422、超限 413、速率限制 429、依赖不可用 503。主要错误码：`VERSION_CONFLICT`、`GRANT_REQUIRED`、`QUALIFICATION_REQUIRED`、`TASK_CLAIMED`、`BUDGET_EXCEEDED`、`DEPENDENCY_UNAVAILABLE`、`MODEL_TIMEOUT`、`UNSUPPORTED_FORMAT`、`EXAM_BANK_EXHAUSTED`。

方括号路径仅为表格简写，例如 `GET /materials` 与 `GET /materials/:id` 是两个路由。内部接口必须验证后端运行凭证且绑定具体员工／任务，不接受模拟人类会话调用内部认领、产物和评审动作。

### 8.3 状态契约

- 知识确认：`pending/confirmed/excluded/conflicted`；原始属性 `self_reported/extracted/inferred/externally_verified` 独立保存。
- 资格：`active/expired/needs_revalidation/suspended`；没有资格不创建假的 L0 证书。
- 任务：`draft/published/blocked/claimed/running/revision_required/awaiting_acceptance/paused/completed/cancelled/voided`。
- 运行：`queued/running/waiting_human/pausing/paused/failed/completed/cancelled`；等待核分或验收对应 waiting_human，不占模型并发槽。
- 授权：`active/revoked`；资料删除单独记录 `deletion_pending/deleted`。

任务 `paused` 保留暂停前状态和原因；恢复返回原可继续状态。取消／完成／作废是终态；重复消息不重新激活。资格过期和授权失效由每次动作校验，不依赖浏览器定时刷新。

## 9. 默认数据、验收与非功能要求

### 9.1 演示数据

创建全新演示空间时提供三份脱敏来源、两个知识包草稿、三名数字员工、两套技能考纲、三卷保留题／技能和一份含 20 个案例的任务草稿。题卷在隔离考题存储，不进入来源检索图。

演示保留“分析员漏判升级风险而失败”和“FAQ 出现退款承诺而退回”两条确定性路径，补学和修订后可通过。这些为样例事件，不声称真实模型测得改善；真实模式成绩使用独立真实运行，不复用样例资格。

任意新文本可人工建立来源与确认声明；演示自动编译／回答只支持预设客服模板，超出范围明确显示“演示适配器不支持此输入，可人工核对或启用真实模型”，不能套用不相关样例结果。

| AC07 | 学习前后测 | 同模式与模型条件、不同等难保留题；练习答案不进入考试上下文 |
| AC08 | 资格 | 79 分或任一硬失败拒绝；80 分无红线经真人核分生效；过期／换配置不可认领 |
| AC09 | 考试隔离 | 执行员工和管理员不能取答案／改分；独立负责人核分有理由与审计 |
| AC10 | 自主组队 | 自治开启后主动提案与认领；缺技能、受众或负载则阻塞，补齐后事件触发重评 |
| AC11 | 同时认领 | 同任务两个提案只一个成功；负载预留不重复，失败方不会启动工作 |
| AC12 | 共享权限 | 原文、图邻居、摘要、会议、产物和下载均不能绕过受众交集 |
| AC13 | 执行与引用 | 分类覆盖 20 案例，FAQ 与风险可查看、可导出；不存在引用／无授权引用拒绝提交 |
| AC14 | 评审退回 | 退款承诺阻止通过；修订需新版本和新评审；执行者无法自验收 |
| AC15 | 最终验收 | 指定有效版本、独立评审、当前权限一起检查；接受和账本事务提交，否则全回滚 |
| AC16 | 积分 | 完整任务 100 积分严格分配 67／33；重复验收和重启不重复；作废记录抵消 |
| AC17 | 等级与经验 | 考试、交付和积分不混同；未确认经验不检索；不更新小林真人绩效或经历 |
| AC18 | 模型模式 | 无 key 可走演示；真实失败不套用样例，模式资格隔离、供应商同意有效 |
| AC19 | 上限与恢复 | 预算／期限到达停止；超时／迟到／重启不假成功，暂停恢复重新验证 |
| AC20 | UI 与权限反馈 | 深链接、键盘、列表替代图、焦点、字段错误、空状态、版本冲突和模式标识齐全 |

运行记录均保存题卷、知识、模型配置指纹、输出与规则版本，可复核但不泄漏隐藏答案或秘密。性能指标必须带运行条件，不能把固定演示当真实收益数据。

### 9.3 性能与稳定性基准

本地验证目标规模：1 个活动工作空间、12 员工、100 份资料、500 条确认声明、100 个任务。元数据读取／普通变更目标 P95 <1 秒，局部知识检索目标 P95 <2 秒；测量不含模型与文件解析，超出不得伪报。

SQLite 是权威持久化，事件、成绩、验收与积分重启后一致。数据库更新不等待远程模型；未结束操作按检查点恢复，不重放已完成奖励。

日志默认只记录关联 ID、时间、状态与错误码；密钥、完整模型上下文和私人资料不写日志。健康页明确是否实际装载 Semantica、是否需要重建、模型是否配置与上次失败，不用统一绿灯隐藏依赖错误。

## 10. 阶段交付与评审点

本 PRD 默认值用于 Prototype，后续真实试点可以通过新版本调整，不静默改变已有考试／任务规则。

本阶段完成后停止，需项目负责人确认，重点查看：

1. 首版以客服知识任务打通闭环，资料支持文本、PDF、DOCX，暂不做 OCR／开放工具。
2. 自治可主动学习、提案与认领；资格最终确认和任务最终验收保留真人。
3. 资格通过阈值 80、有效期 30 天；等级基于有效考核和交付，不依据积分。
4. 固定工作项权重决定奖励，100 积分样例为 67／33，不自动归因真人。
5. 原始资料私有、知识包显式受众与用途；真实模型需资料处理同意。

确认后进入 UI：使用 `ui-ux-pro-max` 生成并核验产品级设计系统与 React 栈建议，产出关键页面与交互原型并再次等待确认；之后才编写应用代码。
