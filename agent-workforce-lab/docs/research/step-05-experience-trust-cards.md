# 步骤 05：经验可信度卡片

> 本步骤把群聊、文档和工作结果中提炼出的经验，转成数字员工可检索、可判断、可追溯的产品对象。

## 一、为什么要做成卡片

长篇复盘适合人阅读，不适合数字员工直接使用。数字员工需要先知道：

- 这条经验讲什么；
- 在什么条件下成立；
- 有哪些证据支持或反驳；
- 当前能用于检索、辅助判断，还是允许执行；
- 新证据出现后，经验是否需要升级、降级或停用。

卡片不是“知识摘要”，而是带证据、边界和使用权限的经验单元。

## 二、卡片结构

| 字段 | 含义 |
|---|---|
| 经验结论 | 一句话说明可复用的方法或判断 |
| 可信等级 | 观察 / 有条件可信 / 已验证 / 稳定 / 冲突 / 已失效 |
| 适用条件 | 系统、版本、环境、现象和前置条件 |
| 允许用途 | 检索、辅助判断、生成排查计划、自动执行 |
| 支持证据 | 结果、变更、指标或复现记录 |
| 反向证据 | 反例、回滚、复发或相互冲突的结论 |
| 缺失验证 | 升级可信等级还缺什么 |
| 最近变化 | 等级变化及原因 |
| 原始来源 | 可回查的群消息、文档、变更和验收记录 |

## 三、状态与使用规则

| 状态 | 产品含义 | 数字员工行为 |
|---|---|---|
| 观察 | 仅出现过，尚未形成可靠结论 | 只能检索和补充证据 |
| 有条件可信 | 有结果支持，但适用边界或验证不完整 | 可辅助判断、生成排查计划 |
| 已验证 | 在明确条件下完成了结果验证 | 可复用；执行仍需单独授权 |
| 稳定 | 多次跨任务验证，且没有有效反例 | 可作为默认建议 |
| 冲突 | 支持与反向证据不能同时解释 | 暂停使用，优先补证 |
| 已失效 | 版本、环境或事实已变化 | 禁止继续使用 |

> **可信度高，不等于允许自动执行。** 自动执行还取决于操作风险、用户授权、环境范围和运行时校验。本案例中的 7 条经验均不允许直接自动执行。

## 四、真实经验卡片

### 卡片 01｜压测前评估 HPA 预扩容

**可信等级：有条件可信**

- **结论：** 高并发压测前，应根据目标流量、单实例承载和扩容时延，评估是否需要预扩容，避免冷启动影响压测结果。
- **适用条件：** 使用 HPA 的在线服务；压测流量会在短时间内陡增。
- **允许用途：** 检索 ✅　辅助判断 ✅　生成计划 ✅　自动执行 ❌
- **支持证据：** 本次压测前提出并完成服务副本调整。
- **反向证据：** 暂无。
- **缺失验证：** 缺少扩容前后指标对照，尚不能证明预扩容对最终结果的独立贡献。
- **最近变化：** 从“群内建议”升级为“有条件可信”，原因是已有实际变更结果。
- **原始来源：** [HPA 预扩容讨论](https://applink.feishu.cn/client/chat/open?openChatId=oc_24d3d69cd83d3a87433e792c29360942&position=356) · [服务副本变更完成](https://applink.feishu.cn/client/chat/open?openChatId=oc_24d3d69cd83d3a87433e792c29360942&position=405)

### 卡片 02｜资源有余量仍需检查 `max-pods`

**可信等级：有条件可信（证据较强）**

- **结论：** 当节点 CPU、内存仍有余量但 Pod 无法继续调度时，应检查节点 `max-pods` 等数量上限，不能只看资源利用率。
- **适用条件：** Kubernetes 集群出现 Pod 调度或扩容受阻，节点资源指标未耗尽。
- **允许用途：** 检索 ✅　辅助判断 ✅　生成计划 ✅　自动执行 ❌
- **支持证据：** 本次排查定位到 Pod 数量上限并完成相关变更。
- **反向证据：** 暂无。
- **缺失验证：** 需要补齐变更前后的调度事件和 Pod 数量对照。
- **最近变化：** 因定位、变更和后续测试连续发生，证据强度提高。
- **原始来源：** [Pod 上限变更](https://applink.feishu.cn/client/chat/open?openChatId=oc_24d3d69cd83d3a87433e792c29360942&position=481) · [短时复现测试结果](https://applink.feishu.cn/client/chat/open?openChatId=oc_24d3d69cd83d3a87433e792c29360942&position=568)

### 卡片 03｜关闭 Trace 只用于隔离变量

**可信等级：已验证的方法边界**

- **结论：** 临时关闭 Trace 可以用于判断链路采集是否影响性能，但不能把“关闭后改善”直接当作最终根因。
- **适用条件：** 性能或稳定性排查需要做单变量对照，且具备关闭 Trace 的安全窗口。
- **允许用途：** 检索 ✅　辅助判断 ✅　生成计划 ✅　自动执行 ❌
- **支持证据：** 本次通过开关 Trace 进行了隔离变量测试。
- **反向证据：** 关闭 Trace 后仍存在其他问题，说明它不能解释全部现象。
- **缺失验证：** 若要升级为根因结论，需要补齐同流量、同配置的对照指标。
- **最近变化：** 从具体操作沉淀为“排查方法及其边界”。
- **原始来源：** [短时复现测试结果](https://applink.feishu.cn/client/chat/open?openChatId=oc_24d3d69cd83d3a87433e792c29360942&position=568) · [阶段总结](https://applink.feishu.cn/client/chat/open?openChatId=oc_24d3d69cd83d3a87433e792c29360942&position=577)

### 卡片 04｜遇到 429 必须先定位返回层

**可信等级：冲突**

- **结论：** 429 不能默认归因于模型限流，必须先确定状态码由客户端、网关、AIGW、模型服务还是其他依赖返回。
- **适用条件：** 调用链出现 HTTP 429 或业务等价错误。
- **允许用途：** 检索 ✅　辅助判断 ❌　生成计划仅限“定位返回层”　自动执行 ❌
- **支持证据：** 群内曾出现“模型限流”的初步判断。
- **反向证据：** 后续排查涉及 AIGW 和其他链路问题，原归因不足以成立。
- **缺失验证：** 需要请求 ID、返回头、各层日志与限流配置形成完整证据链。
- **最近变化：** 原经验“429 默认来自模型限流”被反例推翻，卡片自动降级为冲突。
- **原始来源：** [AIGW 与 ES 阶段总结](https://applink.feishu.cn/client/chat/open?openChatId=oc_24d3d69cd83d3a87433e792c29360942&position=577)

### 卡片 05｜AIGW 空用户 ID 与特定超时

**可信等级：有条件可信**

- **结论：** 在本次特定版本和调用路径中，空用户 ID 与超时现象有关；遇到同类问题可优先核查该字段，但不能跨版本泛化。
- **适用条件：** 相同 AIGW 版本、调用路径和请求结构。
- **允许用途：** 检索 ✅　辅助判断 ✅　生成计划 ✅　自动执行 ❌
- **支持证据：** 阶段总结记录了该字段与超时的关联。
- **反向证据：** 缺少跨版本、跨流量的复现。
- **缺失验证：** 需要最小复现、修复版本及修复前后对照。
- **最近变化：** 增加“限定版本/路径”边界，防止把局部问题泛化。
- **原始来源：** [AIGW 与 ES 阶段总结](https://applink.feishu.cn/client/chat/open?openChatId=oc_24d3d69cd83d3a87433e792c29360942&position=577)

### 卡片 06｜OpenSearch 磁盘水位与分片排查

**可信等级：有条件可信**

- **结论：** OpenSearch 出现写入、分片分配或集群异常时，应同时检查磁盘水位、分片状态和相关配置，不能只看服务是否存活。
- **适用条件：** OpenSearch 出现性能下降、写入异常或分片异常。
- **允许用途：** 检索 ✅　辅助判断 ✅　生成计划 ✅　自动执行 ❌
- **支持证据：** 本次排查形成处理进展并创建了对应变更。
- **反向证据：** 暂无。
- **缺失验证：** 需要补齐变更前后磁盘、分片和错误率指标，以及最终验收结果。
- **最近变化：** 从排查记录升级为有条件可信，尚未达到稳定经验。
- **原始来源：** [OpenSearch 处理进展](https://applink.feishu.cn/client/chat/open?openChatId=oc_24d3d69cd83d3a87433e792c29360942&position=761) · [OpenSearch 变更创建](https://applink.feishu.cn/client/chat/open?openChatId=oc_24d3d69cd83d3a87433e792c29360942&position=789)

### 卡片 07｜“1400 并发持续 48 小时已通过”

**可信等级：观察（未验证）**

- **结论：** 当前证据不能证明 1400 并发持续 48 小时已经通过。
- **适用条件：** 仅用于追踪本次压测目标与验收缺口。
- **允许用途：** 检索 ✅　辅助判断 ❌　生成计划 ❌　自动执行 ❌
- **支持证据：** 群内存在阶段性测试和进展信息。
- **反向证据：** 未找到完整 48 小时最终验收报告。
- **缺失验证：** 需要明确时间窗、流量口径、成功率、延迟、资源指标及验收人。
- **最近变化：** 因缺少最终报告，保持未验证，不得写入数字员工的已掌握能力。

## 五、数字员工怎样使用

1. 接到问题后，按现象、系统、版本和环境检索卡片。
2. 先过滤“冲突、已失效、条件不匹配”的经验。
3. 基于可用卡片生成**候选判断和排查计划**，同时展示依据与未知项。
4. 涉及变更时，重新检查授权、风险和运行环境；卡片本身不授予执行权。
5. 执行结果自动回流为新证据，触发卡片升降级，而不是要求专家逐条确认。

## 六、经验如何自动升降级

```text
新工作结果进入
      ↓
匹配经验与适用条件
      ↓
结果支持 ──→ 增加支持证据 ──→ 多次独立验证后升级
      │
      ├─ 结果相反 ──→ 增加反向证据 ──→ 降级或标记冲突
      │
      └─ 环境变化 ──→ 适用条件失效 ──→ 标记已失效
```

触发降级的典型事件：

- 同条件下问题复发；
- 变更被回滚；
- 新版本改变了原机制；
- 验收结果与原结论相反；
- 原始授权或证据被撤回。

## 七、禁止直接执行的卡片

当前 7 张卡片全部禁止自动执行，原因包括：

- 涉及线上扩缩容、配置或基础设施变更；
- 证据仍有缺口；
- 适用范围受版本和环境限制；
- 存在冲突或尚未完成最终验收。

数字员工可用这些卡片生成排查建议，但必须经过任务权限、风险策略和运行时校验。

## 八、验收标准

- 用户 10 秒内能看懂结论、可信等级和允许用途；
- 每张卡片都能回查原始证据；
- 适用条件不匹配时不会被推荐为结论；
- 冲突卡不会参与自动判断；
- 新结果可自动增加支持或反向证据；
- 可信等级变化有明确原因和时间记录；
- 可信度与执行权限分开管理；
- 不要求专家逐条审阅，只在冲突、高风险或证据不足时请求人工介入。
