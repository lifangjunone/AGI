# 分身学习界面：从宣传标题回到工作对象

## 本次判断

用户提供的三张截图：入口、分身首页、学习空间均被超大宋体标题支配。错误来自设计判断，不来自任何已核实精品产品的要求。当前源文件已有后置字号覆盖，但不能据此断言截图中的运行版本已更新，更不能把缩字当成产品完成。

本轮仅新增隔离的设计评审原型，不修改正式 React、后端、数据库或其他项目。设计方向未获用户选择。

## 技能与取舍

- `product-ui-director`：先作隔离对照，停在方向选择门槛，不直接替换正式界面。
- `frontend-design`：产品独特点是知识边界与成长证据，而非宣传标题。取消营销 Hero、序号装饰、强酸绿／宋体组合。三个方向用相同样例比较。
- `ui-ux-pro-max`：针对可读字号和标题层级查询，采用可见标签、顺序标题、移动正文 16px、非纯色状态。首次宽泛 hierarchy 查询仅部分相关，收窄为 heading readable typography；不把结果包装成精品视觉设计。
- `playwright-skill`：真实浏览器截图和表单操作验证。

## 三个方向

| 方向 | 核心机制 | 代价 |
|---|---|---|
| A 学习收件箱 | 学习记录与来源／回答并排，集中处理少数疑问 | 数字分身情感身份较弱 |
| B 分身工作室 | 分身形象和学习目标常驻，围绕当前教学对话 | 批量处理较慢，窄屏角色栏折叠 |
| C 成长路线 | 资料、边界、方法、考试与印记形成可查看的证据链 | 操作密度较低，适合讲故事但不应强制每天走流程 |

建议 A 作为工作主布局，吸收 B 的稳定身份；C 作为成长详情而非每次首页。此为建议，不是用户已选方向。

## 渲染与修订

位置：`design/review/learning-workspace/`；本地独立静态服务端口 43224。

1. 第一遍实际渲染三个方向与四种尺寸。截图发现桌面操作按钮接近折线，移动端隐藏列表后没有记录切换能力。
2. 取消原型内设计解释条，压缩标题与身份区；B/C 和手机增加有标签的记录选择器。不是仅验证不溢出。
3. 首次自动化发现 hash 切换未触发布局更新，补 hashchange 并收窄 heading 选择器。

## 验证范围与未完成

可重复脚本 `check.cjs`：三个布局 × 1440×900、1024×768、768×1024、375×812；标题不超过 28px、无整页横向溢出；记录切换保留输入；复述回显原输入；确认仅到待运营考核；原生 dialog Escape；首次创建保留姓名；手机记录切换。

所有内容为虚构脱敏样例。回答直接回显而非模型理解，页面刷新重置；文件只展示文件名，没有上传或解析。不能作为自动采集、学习、考试、真实权限、后端产品完成的证明。

未完成：用户视觉评审、正式双入口整体设计、真实数据接入及业务真实性、低人工学习、完整自主任务协作。当前没有达到总目标，不进入“产品级完成”结论。
