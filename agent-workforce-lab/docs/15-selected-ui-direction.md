# Agent Workforce Lab 选定 UI 方向

## 当前评审状态 · 2026-10-30

用户已选择员工端 **C · 成长路线**，进入正式 React 实现阶段。运营端方向仍沿用已验证的任务现场，不把员工成长与运营调度重新混在同一个入口。

当前隔离对照在 `design/review/learning-workspace/`：

- 员工端 A 学习收件箱、B 分身工作室、C 成长路线；
- 运营端任务现场、成员分工板、工作时间线。

选定方向的正式含义：

- 首页先回答“分身当前成长到哪一步、为什么还不能接任务、下一步谁要做什么”；
- 资料、澄清、方法、考试、印记是有真实状态支撑的五个关口，不是装饰性时间线；
- 学习页将路线与当前操作并排，首页负责理解，学习页负责行动；
- 保留稳定的分身身份、来源证据、授权状态、考试门禁与能力边界；
- 拒绝超大宋体、营销 Hero、口号式首屏和无行动意义的指标卡。

双入口已由用户明确决定：员工端培养本人分身；专门运营人员负责发布、考核、调度和验收。因此下方“首页同时提供三个核心动作”不再适用于同一账号操作面；应在各自入口提供对应职责，权限由服务端保证。

## 历史视觉命题

## 视觉命题

**让用户同时看见两件事：经验如何成为能力，能力如何承担工作。**

正式产品以“能力铸造线”为整体叙事骨架，融合：

- “工作剧场”的在场感，用于任务执行、求助、成员变化和成果状态；
- “人才操作系统”的证据与边界表达，用于能力档案、试岗和放权治理。

## 页面映射

| 产品对象 | 主要视觉表达 |
|---|---|
| 真人经验 | 有授权和来源的输入，不表现为普通文件列表 |
| 数字员工 | 有连续身份、岗位和当前行动的工作主体 |
| 能力 | 从学习到试岗、可接单的状态链，附证据与边界 |
| 任务 | 持续存在的工作现场，展示独立、求助、成组和验收 |
| 成果 | 可检查的工作对象，包含证据、风险和真人决定 |

## 首页原则

首屏必须直接提供三个核心动作：

1. 让数字员工学习；
2. 发布任务；
3. 查看任务进度与成果。

首页不再以 KPI 卡片为核心。它应优先回答：

- 哪些真实经验正在变成能力；
- 哪位数字员工下一步要跨过什么门槛；
- 哪些数字员工正在独立工作或协作；
- 用户当前只需要做哪一个不可替代的决定。

## 实现约束

- 保留现有 API、权限、路由、错误和空状态。
- 不用动画冒充学习或任务执行。
- “学会”“可接单”“完成”必须有试岗、任务证据或真人验收。
- 先改全局壳层和首页，截图验证后再把同一语言扩展到员工、任务和治理页面。
