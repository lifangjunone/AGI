# Agent Workforce Lab 产品蓝图

> 本文覆盖 `09`—`11` 中将产品收窄为固定 Oncall 演示流程的部分。
> Oncall 案例仍是第一条真实证据链，但不再作为产品信息架构。

## 1. 产品目标

### 一句话

**让真实员工无需额外写教程，系统就能从日常工作中持续孵化出有证据、有边界、能逐步接任务的数字员工。**

### 用户购买的不是 Agent

用户真正购买的是三件事：

1. 专家经验不会随着人员流动丢失；
2. 数字员工是否会做，有可核查证据；
3. 组织能控制它做到哪一步、何时必须找人。

### 北极星结果

```text
每周新增的“可由数字员工可靠完成、且真人投入下降”的工作类型
```

不能用文档数量、对话轮数、知识片段数或创建 Agent 数量代替。

## 2. 产品主循环

```text
真实工作持续发生
        ↓
学习中心自动发现一段完整工作
        ↓
经验编译器还原目标、证据、判断、动作、结果和边界
        ↓
数字员工吸收为候选能力
        ↓
系统用历史变体和新任务进行试岗
        ↓
通过后获得有限能力印记
        ↓
先影子执行，再建议执行，再受控执行
        ↓
真实结果、接管与返工继续校准能力
```

这是一条永久循环，不是一次性的“导入—生成—结束”向导。

## 3. 产品中的三个核心对象

### 3.1 真实员工

不是被监控对象，而是经验来源与最终责任人。

系统展示：

- 系统从他的工作中识别到哪些能力；
- 哪些来源已授权；
- 哪些判断仍不确定；
- 数字员工替他减少了多少重复工作；
- 哪些内容随时可以撤回。

### 3.2 数字员工

是长期存在的工作主体，不是一次模型调用。

它具有：

- 岗位目标；
- 当前正在学习的能力；
- 已获得的印记及适用边界；
- 最近试岗和真实工作记录；
- 失败、接管、补学记录；
- 可用工具与放权等级；
- 版本化的知识和行为配置。

### 3.3 工作能力

产品的核心资产不是文档，而是“可验证能力”：

```text
能力定义
+ 适用场景
+ 真实来源
+ 判断点与 SOP
+ 试岗任务集
+ 评分器
+ 真实结果
+ 禁止范围
+ 最近验证时间
```

## 4. 用户每天为什么打开产品

首页不是案例导航，也不是大屏，而是“孵化工作台”。

### 今日需要我处理

只出现高价值例外：

- 两条来源结论冲突；
- 高风险经验需要授权；
- 数字员工连续失败；
- 影子结果与真人结果明显不一致；
- 某项能力准备升级放权；
- 来源撤回影响现有能力或任务。

每项应能在几十秒内完成：接受、纠正、限制范围、延后或撤回。

### 数字员工成长

每位数字员工显示：

- 正在学习什么；
- 最近从哪些真实工作中学到；
- 哪项试岗通过/失败；
- 当前能接什么、不能接什么；
- 下一次升级还缺什么证据。

### 正在工作的数字员工

展示真实任务：

- 当前目标；
- 已完成到哪一步；
- 引用了哪些能力；
- 是否遇到能力缺口；
- 是否需要真人接管或邀请其他数字员工；
- 结果和验收状态。

## 5. 六个产品工作区

### 5.1 学习中心

目标：低打扰地发现可学习工作。

能力：

- 连接 Oncall、飞书文档、工单、变更、AI 工具 Trace；
- 按一个工作目标聚合跨系统素材；
- 显示采集范围、权限和脱敏状态；
- 自动发现“完整案例”和“缺失材料”；
- 支持用户主动标记“这次值得学习”。

体验原则：

- 不叫“旁听”“监控”；
- 不默认录屏或键盘采集；
- 不要求真人复制粘贴；
- 优先复用已经存在的业务记录。

### 5.2 经验编译

目标：把工作记录变成数字员工能使用的经验。

自动输出：

- 工作目标和结果；
- 时间线；
- 当时可见事实；
- 真人/AI 的推断；
- 尝试过的动作；
- 失败尝试；
- 决策点和理由；
- 适用条件与禁止范围；
- 未确认项和反向证据。

人工只处理异常，不逐条确认正常内容。

### 5.3 数字员工

目标：查看并管理持续成长的工作主体。

单个员工页面以能力地图为核心：

- 待学习；
- 学习中；
- 待试岗；
- 影子工作；
- 已授权工作；
- 暂停/失效。

点击一项能力能回查来源、试岗、真实结果和边界。

### 5.4 试岗与校准

目标：证明数字员工是否真的掌握。

系统从历史案例的时间截断、相似变体和真实失败生成任务集，记录完整轨迹和结果。

评分顺序：

```text
安全否决
→ 可验证结果
→ 工具调用与过程规则
→ 模型评分
→ 少量人工校准
```

### 5.5 任务与协作

目标：让已具备资格的数字员工承担真实工作。

任务进入后：

- 数字员工先给出能否承担、依据和缺口；
- 一人能完成则独立开始；
- 遇到能力缺口可邀请一名员工；
- 第三名执行成员加入时建立任务组；
- 原任务、已有证据和产物保持连续；
- 运行引擎校验资格、授权、负载和风险。

### 5.6 结果与治理

目标：决定是否继续相信和放权。

展示：

- 任务结果与验收；
- 真人接管和返工；
- 能力成功率与样本量；
- 适用边界变化；
- 模型/知识/工具版本影响；
- 授权撤回影响；
- 能力升级、暂停或失效。

## 6. 能力成长和放权

“印记”保留，但它不是游戏徽章，而是可审计资格。

| 等级 | 证据要求 | 允许工作 |
|---|---|---|
| 新手印记 | 历史案例学习 + 独立试岗通过 | 只读分析、生成建议 |
| 熟手印记 | 多个新案例通过 + 影子结果稳定 | 影子执行、低风险草稿 |
| 高手印记 | 多次真实任务验收 + 低接管率 | 受控执行、关键动作需审批 |
| 专家印记 | 跨变体稳定 + 能识别新边界并指导其他员工 | 在明确策略内自治，持续抽检 |

任何等级都绑定：

- 能力范围；
- 来源与版本；
- 工具和模型条件；
- 样本量；
- 最近验证时间；
- 禁止动作；
- 降级与失效条件。

## 7. 第一版产品范围

第一版不是“只有 Oncall 的 Demo”，而是“以 Oncall 为首个模板的通用产品骨架”。

### 必须真实可用

1. 创建组织、账号、真实员工和数字员工；
2. 配置来源连接器及授权；
3. 从 Oncall + 飞书文档生成一个真实案例；
4. 同样的入口可以导入第二个新案例，不改代码；
5. 自动生成并持久化工作事件、经验和来源关系；
6. 把经验分配给一个数字员工学习；
7. 自动生成试岗任务并运行真实模型作答；
8. 保存完整轨迹，由独立评分器输出结果；
9. 生成有边界的能力印记；
10. 用一个新任务完成影子试岗并记录真人对照结果；
11. 来源撤回后影响对应经验、试岗和印记；
12. 重启后全部状态恢复。

### 第一版不做

- 真实生产写操作；
- 全电脑后台监控；
- 人格克隆；
- 现金奖励；
- 公网多租户部署；
- 无边界的自主 Agent；
- 用预置回答冒充真实模型运行。

## 8. 产品级验收门槛

以下任意一条不满足，都不能称为产品版本：

1. 不能导入一个新的案例；
2. 数据或结论无法回查来源；
3. 经验编译只能靠写死规则适配一个案例；
4. 数字员工没有长期能力档案；
5. 试岗只播放预置答案；
6. 评分没有真实轨迹或结果证据；
7. 通过后没有能力边界和放权限制；
8. 专家仍需逐条检查全部内容；
9. 无法撤回授权或使能力失效；
10. 页面仍以“演示步骤”为主要导航；
11. 第二位员工、第二项能力或第二个案例需要改代码；
12. 系统重启后关键状态丢失。

## 9. 现有系统差距

| 领域 | 当前状态 | 产品化缺口 |
|---|---|---|
| 账号 | 本地注册登录 | 缺组织、成员、角色与数据隔离 |
| 资料 | 手工文本/文件导入 | 缺真实来源连接器、同步与采集任务 |
| 知识 | 通用 Source + Semantica 检索 | 缺案例、事件、决策点、经验版本与证据图 |
| 数字员工 | 姓名、岗位、单技能 | 缺长期能力地图、学习计划和运行版本 |
| 考试 | 通用提示 + 三项字符串规则 | 缺真实 ReplayCase、轨迹、grader 和结果状态 |
| 任务 | 有状态机和 1→2→3 组队 | 能复用，但资格必须改为真实能力印记 |
| UI | 固定 Oncall 演示导航 | 需要重建为孵化工作台和真实数据工作流 |

## 10. 实施顺序

### 里程碑 A：产品底座

- 组织与权限；
- 案例、来源、事件、经验、数字员工、试岗、印记数据模型；
- 审计和版本依赖。

### 里程碑 B：真实案例编译

- Oncall/飞书连接器；
- 脱敏和素材包；
- 时间线与经验编译；
- 例外审核队列。

### 里程碑 C：真实学习与试岗

- 能力分配；
- ReplayCase 生成；
- Agent 轨迹运行；
- grader 与印记。

### 里程碑 D：影子工作

- 新任务进入；
- 数字员工方案与真人结果并行；
- 差异校准；
- 低风险放权。

### 里程碑 E：协作与规模化

- 中途求助；
- 三人成组；
- 多能力、多员工、多案例；
- 运营与治理指标。
