## 2. 设计目标

### 2.1 用户 5 分钟内必须看懂

```text
真实工作记录
  ↓
系统编译经验
  ↓
数字员工试岗
  ↓
系统按证据评分
  ↓
能力印记有边界
```

### 2.2 设计必须回答四个问题

每个关键页面都要回答：

1. 证据在哪里？
2. 过程在哪里？
3. 评分依据在哪里？
4. 能力边界在哪里？

如果一个页面不能回答这四个问题，就说明它偏离产品主线。

## 3. 设计方向

### 3.1 主方向

**可信工作台 + 数字员工试岗室。**

它不是：

- AI 小镇；
- 纯聊天工具；
- 普通后台；
- 监控大屏；
- 数字员工社交广场。

它是一个把真实工作过程转成可验证能力的企业工作台。

### 3.2 视觉气质

| 维度 | 设计选择 |
|---|---|
| 感受 | 可信、冷静、专业、可核查 |
| 信息密度 | 高，但用分区和留白降低压力 |
| 色彩 | 深蓝建立信任，绿色表示通过和行动，红色只用于否决 |
| 形状 | 轻圆角、硬朗边线，避免卡通感 |
| 动效 | 只用于证据解锁、阶段推进、风险触发 |
| 角色表现 | 小禾是数字员工对象，不拟人化成真人员工 |

## 4. 全局设计系统

### 4.1 色彩 token

| Token | 色值 | 用途 |
|---|---|---|
| `--color-primary` | `#1E3A5F` | 顶栏、主标题、当前阶段 |
| `--color-secondary` | `#2563EB` | 链接、可操作证据 |
| `--color-accent` | `#16A34A` | 通过、开始、确认 |
| `--color-background` | `#F8FAFC` | 页面底色 |
| `--color-foreground` | `#0F172A` | 主文本 |
| `--color-card` | `#FFFFFF` | 卡片、面板 |
| `--color-muted` | `#E9EEF5` | 次级背景 |
| `--color-muted-foreground` | `#475569` | 次级文本 |
| `--color-border` | `#CBD5E1` | 边框、分隔 |
| `--color-destructive` | `#DC2626` | 一票否决、危险回答 |
| `--color-ring` | `#1E3A5F` | 焦点环 |

补充状态：

| 状态 | 背景 | 文本 | 说明 |
|---|---|---|---|
| 观察 | `#EEF2F7` | `#334155` | 尚未验证 |
| 有条件可信 | `#EAF2FF` | `#1D4ED8` | 可辅助判断 |
| 已验证 | `#EAF7EF` | `#15803D` | 已有证据支持 |
| 冲突 | `#FFF7ED` | `#C2410C` | 存在反向证据 |
| 一票否决 | `#FEF2F2` | `#B91C1C` | 高危，不通过 |
| 待人工复核 | `#F5F3FF` | `#6D28D9` | 需要人介入 |

颜色不可作为唯一状态表达，必须配文字和图标。

### 4.2 字体

| 层级 | 字体 | 用法 |
|---|---|---|
| 标题 | Lexend / 系统无衬线 | 页面标题、核心模块标题 |
| 正文 | Source Sans 3 / 系统无衬线 | 中文正文和说明 |
| 等宽 | SFMono / Menlo / Consolas | Flow ID、位置、证据 ID、代码片段 |

字号：

- H1：28 / 36；
- H2：22 / 30；
- H3：18 / 26；
- 正文：16 / 24；
- 次文案：14 / 22；
- 标签：12 / 18，只用于辅助信息。

### 4.3 间距与布局

使用 4 / 8 / 12 / 16 / 24 / 32 / 48 间距系统。

桌面：

- 顶栏：64px；
- 内容左右边距：32px；
- 主容器最大宽度：1400px；
- 12 栅格；
- 卡片间距：16px；
- 面板内边距：20px。

移动：

- 内容边距：16px；
- 底部固定操作栏高度不超过 72px；
- 滚动区域预留底部内边距，避免操作栏遮挡。

### 4.4 图标

- 使用一致的 SVG 图标体系；
- 不使用 emoji 作为结构图标；
- 装饰图标设置为隐藏语义；
- 独立按钮图标必须有 accessible name；
- 图标不能单独承载状态。

### 4.5 动效

动效只用于：

1. 证据解锁；
2. 阶段推进；
3. 风险触发；
4. 评分状态变化。

建议：

- 普通状态变化：160–220ms；
- 证据解锁：240–320ms；
- 风险触发：即时出现 + 轻微强调；
- 自动播放可暂停；
- 支持减少动态效果。

不做：

- 粒子；
- 地图漫游；
- 角色走路；
- 闪烁；
- 长时间 loading。

## 5. 信息架构

顶层导航：

```text
首页｜案例编译｜经验卡片｜试岗题｜试岗室｜评分结果
```

虽然 Prototype 需求中是 5 个入口，本次 UI 建议把“试岗题”和“试岗室”拆开。原因：

- 试岗题是考试配置；
- 试岗室是执行现场；
- 分开后更容易解释“题怎么来的”和“员工怎么答”。

顶部全局状态条：

```text
案例：HiAgent 长稳压测异常排查
数字员工：小禾
模式：无密钥演示
安全：只读，不连接生产
```

## 6. 页面设计

### 6.1 首页：演示控制台

目标：让用户立刻理解产品故事。

布局：

```text
┌──────────────────────────────────────────────┐
│ 顶部导航 + 全局状态条                         │
├──────────────────────┬───────────────────────┤
│ 价值主张 + 当前案例   │ 闭环进度 Stepper       │
├──────────────────────┴───────────────────────┤
│ 三张证明卡：来源真实 / 经验有边界 / 先试岗再上岗 │
├──────────────────────────────────────────────┤
│ 当前数字员工：小禾，待试岗                     │
└──────────────────────────────────────────────┘
```

主文案：

```text
把真实员工的工作过程，编译成数字员工可验证的能力。
```

副文案：

```text
当前演示案例：HiAgent 长稳压测异常排查。
目标：验证小禾是否具备“压测问题诊断·新手印记”。
```

主按钮：

```text
开始查看案例编译
```

次按钮：

```text
查看试岗题
```

首页必须有安全提示：

```text
只读演示：不连接生产、不执行变更、不展示真实凭据。
```

### 6.2 案例编译页

目标：证明材料来自真实工作记录，并展示系统如何结构化。

桌面布局：

```text
左 24%：来源列表
中 42%：证据时间线
右 34%：结构化抽取详情
```

来源列表：

| 来源 | 状态 | 展示 |
|---|---|---|
| Oncall 群聊 | 已读取 | 条数、时间范围、脱敏状态 |
| 飞书文档 | 已读取 | 文档名、段落数 |
| 工单 | 已读取 | Flow ID 脱敏 |
| 变更记录 | 已读取 | 只展示变更状态 |

时间线节点：

1. 初始压测异常；
2. HPA / 副本讨论；
3. Pod 上限问题；
4. 短时复现测试；
5. AIGW 空用户 ID 线索；
6. OpenSearch 磁盘和分片问题；
7. 48 小时验收缺失。

每个节点必须有标签：

- 事实；
- 推断；
- 动作；
- 结果；
- 未确认；
- 事后结论。

右侧详情区展示：

```text
节点标题
时间
类型
原始证据摘要
系统抽取结果
是否考试初始可见
为什么这样判断
```

关键交互：

- 点击时间线节点更新右侧详情；
- 切换“考生初始可见 / 评分器完整视角”；
- 点击“预览试岗题开场”。

### 6.3 经验卡片页

目标：把长流程沉淀成可复用、可验证、有边界的经验。

布局：

```text
左：卡片网格
右：选中卡详情
```

卡片内容：

```text
标题
可信等级
一句话结论
允许用途
禁止误用
证据数量
```

七张卡片必须完整展示：

1. HPA 预扩容；
2. `max-pods`；
3. Trace 隔离变量；
4. 429 返回层；
5. AIGW 空用户 ID；
6. OpenSearch 磁盘与分片；
7. 48 小时验收未验证。

卡片视觉：

- 已验证 / 有条件可信：蓝绿系；
- 冲突：橙色；
- 未验证：灰蓝；
- 自动执行关闭：统一灰色锁定标签。

右侧详情：

```text
结论
适用条件
支持证据
反向证据
缺失验证
允许用途
禁止自动执行原因
```

### 6.4 试岗题页

目标：让用户看懂历史案例如何被编译成考试。

布局：

```text
顶部：考生视角 / 评分器视角切换
左：开场题面
中：可查询动作
右：评分规则与一票否决
底：Inject 列表，仅评分器视角可见
```

考生视角只显示：

- 初始任务；
- 初始可见事实；
- 可查询动作；
- 最终提交格式。

评分器视角显示：

- Inject；
- 评分矩阵；
- 一票否决；
- 答案泄漏检查；
- 证据索引。

必须有明显提示：

```text
数字员工一开始不能看到后续答案。
```

### 6.5 试岗室

目标：展示数字员工如何在有限信息下逐步判断。

这是核心页面。

桌面布局：

```text
┌──────────────────────────────────────────────────────────────┐
│ 阶段条：初始题面 → 查询证据 → 提交判断 → 评分                 │
├───────────────┬────────────────────────┬─────────────────────┤
│ 当前可见信息   │ 小禾的动作与判断         │ 实时评分器            │
│ 证据/Inject    │ 查询、理由、结果、下一步 │ 维度、风险、否决项     │
├───────────────┴────────────────────────┴─────────────────────┤
│ 已解锁证据时间轴                                               │
└──────────────────────────────────────────────────────────────┘
```

左栏：当前可见信息

- 开场题面；
- 已解锁 Inject；
- 当前不能下的结论；
- 证据来源链接。

中栏：小禾动作

每一步用“动作卡”展示：

```text
我现在判断：
我想查询：
查询理由：
查询结果：
下一步：
```

右栏：实时评分器

| 检查项 | 状态 |
|---|---|
| 事实与推断分离 | 通过 / 风险 |
| Pod 调度约束 | 已检查 / 未检查 |
| 429 返回层 | 已检查 / 未检查 |
| 验收口径 | 安全 / 风险 |
| 越权变更 | 安全 / 一票否决 |
| 虚构验收 | 安全 / 一票否决 |

底部：证据时间轴

- 显示已解锁证据；
- 未解锁证据以锁定状态展示；
- 点击证据同步定位到左栏。

操作区：

- 上一步；
- 下一步；
- 自动播放；
- 暂停；
- 切换演示模式。

三种演示模式：

| 模式 | UI 结果 |
|---|---|
| 好回答 | 蓝绿主线，高分，通过，新手印记 |
| 漂亮废话 | 黄色提醒，低分，不通过 |
| 危险回答 | 红色否决，一票否决，不生成印记 |

### 6.6 评分与能力印记页

目标：让用户相信“通过 / 不通过”不是主观判断。

布局：

```text
顶部：总结果
左：评分维度
中：关键轨迹回放
右：能力印记卡
底：下一步建议
```

顶部总结果：

- 通过；
- 未通过；
- 一票否决。

评分维度：

使用 bullet / progress 组合，不使用大仪表盘。

维度：

- 事实与推断分离；
- 调度约束识别；
- 429 证据链；
- 经验边界；
- 验收口径；
- 安全与权限；
- 行动可执行性；
- 表达质量。

能力印记卡：

```text
压测问题诊断·新手印记
等级：新手
来源：HiAgent 长稳压测异常排查
通过证据：考试得分、关键判断、引用证据
边界：仅代表诊断计划能力，不代表可执行生产变更
状态：有效 / 待复核 / 未获得
```

## 7. 响应式设计

### 7.1 桌面 1440×900

- 使用完整三栏 / 四区布局；
- 顶部状态条常驻；
- 试岗室显示三栏 + 底部时间线；
- 评分页显示三列。

### 7.2 1024×768

- 试岗室变为双栏；
- 左侧：当前信息 + 证据；
- 右侧：动作 + 评分；
- 底部时间线变为右侧可折叠模块。

### 7.3 768×1024

- 使用 tabs：

```text
信息｜动作｜评分｜证据
```

- 顶部 stepper 保留；
- 评分器不浮动，作为独立 tab。

### 7.4 375×812

- 单栏卡片；
- 底部固定操作栏；
- 复杂时间线变为线性事件列表；
- 不强行展示三栏；
- 所有关键按钮不低于 44px 高。

## 8. 可访问性与专业检查

必须满足：

- 文本对比度不低于 4.5:1；
- 状态不只靠颜色；
- 所有按钮可键盘操作；
- 焦点环可见；
- 固定顶部 / 底部不遮挡焦点；
- 错误和否决项有集中摘要；
- 图表有文字表格备选；
- 自动播放可暂停；
- 减少动态效果时直接显示最终状态；
- 不使用 emoji 作结构图标；
- 图标控件有可访问名称。

## 9. 与旧“广场 v2”设计的关系

旧设计系统 MASTER 中记录了“可观察的数字员工广场 v2”。

本次不删除、不覆盖，但本页面设计明确覆盖它。

原因：

- 当前 PRD v0.1 聚焦“学习与试岗”，不是任务组队；
- 广场更适合未来“任务发布与协作执行”阶段；
- 当前最需要讲清楚的是证据、试岗、评分和能力边界；
- 如果现在做广场，会削弱产品核心验证逻辑。

保留策略：

| 阶段 | 使用方向 |
|---|---|
| v0.1 学习与试岗 | 可信工作台 + 试岗室 |
| v0.2 任务发布与组队 | 可考虑重新引入广场 / 空间协作 |

## 10. UI 验收标准

### 10.1 产品理解

用户不读长文也能理解：

- 数据来自真实工作记录；
- 系统抽取经验；
- 数字员工先试岗；
- 评分依据是轨迹和证据；
- 能力印记有边界。

### 10.2 演示闭环

必须能按页面讲完：

```text
首页
→ 案例编译
→ 经验卡片
→ 试岗题
→ 试岗室
→ 评分结果
```

### 10.3 关键状态

必须有三种状态设计：

| 状态 | 结果 |
|---|---|
| 好回答 | 高分，通过，获得新手印记 |
| 漂亮废话 | 低分，不通过 |
| 危险回答 | 一票否决，不生成印记 |

### 10.4 边界清楚

所有页面都不能暗示：

- 已连接生产；
- 已执行真实变更；
- 已通过 48 小时压测；
- 数字员工已经可直接接任务；
- 分数等同于真人绩效。
