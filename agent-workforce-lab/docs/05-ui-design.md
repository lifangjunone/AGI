# Agent Workforce Lab：UI 设计说明

> 2026-10-24 · 第三阶段评审稿。PRD 已获确认；UI 确认后再开始应用编码。

## 当前评审版本：v2 数字员工广场

用户否定 v1 管理看板，并明确要求直观展示数字员工自动组队或独立执行。新的推荐入口为 [广场交互原型](../design/prototype/plaza.html)，v1 文件保留作对照，不再作为设计主方向。

v2 以参考图片的暖色等距广场为视觉基础，原创构建知识馆、考核站、任务公告栏、组队工坊、独立工作室和交付中心。主区域是可观察的工作空间，右侧展示当前任务、匹配理由、成员和五步进度，下方是团队／单人任务池。

### 体验路径

1. 点击双人任务，逐步观察发现目标、匹配资格、邀请队友、进入组队工坊、提交与验收；邀请阶段显示连线。
2. 点击单人任务，观察员工覆盖全部技能、独立认领、进入单人工位并提交；不为了展示多 Agent 而强制组队。
3. 点击员工查看姓名、岗位、知识背景、考试条件和当前职责。
4. 点击知识馆／学习站查看知识来源与考核，点击交付中心查看产物和验收边界。
5. 支持手动下一步、自动播放、暂停、重置；隐藏标签页或弹窗打开时不推进。
6. 小屏默认列表保证可读，可手动切换空间；地图不是唯一操作路径。

本轮重新使用 `ui-ux-pro-max`，并按 Oil UI 的参考图构图、减法和截图验看方法打磨。数据库未匹配参考图的等距风格，不照搬 VisionOS／营销模板；搜索与设计取舍记录在 MASTER。

### 验证与边界

已在可见 Chromium 验证 375、768、1024、1600px 无整页横向溢出；团队与单人五步、验收必选核查、员工详情、列表替代、Escape 与减少动态效果均可操作。截图中发现屋顶定位问题后已修正。

设计演示不调用后端、模型、SDK，不写真实资格与奖励；角色动作和过程为样例。单人任务是本次请求新增的 UI 能力表达，未来实现时需将“允许单个合格员工覆盖全部职责”与任务模板／PRD 补齐，不在本阶段悄悄扩展后端业务。

没有完成独立视觉评分，当前为主 Agent 自检；尚未宣称全面无障碍或生产验证通过。截图：`plaza-desktop.png`、`plaza-team.png`、`plaza-solo.png`、`plaza-mobile.png`（均在原型目录）。以下 v1 记录保留作历史，不覆盖本节。

## 2. 视觉与信息架构

采用“数字员工工作室”：暖灰浅色背景、白色内容面、深蓝导航、青绿主要行动。空间感只用于呈现成员职责与交付状态，不使用像素小镇、无目的聊天、自动播放或游戏化奖励动画。

`ui-ux-pro-max` 提供了适用的简洁网格、清晰层级、语义控件、焦点与响应式指导。两次设计系统检索仍返回营销页面模式，不作为应用页面结构依据；配色与工作空间架构的设计调整在 MASTER 中明确记录。

八个视图：

| 视图 | 核心判断与主要动作 |
| --- | --- |
| 工作总览 | 完整生命周期、当前团队与真人待办，进入任务现场 |
| 资料贡献 | 资料、事实核对、排除敏感项、贡献与访谈表单预览 |
| 知识图谱 | 来源、方法、条件与红线，关系／列表切换、撤回影响 |
| 数字员工 | 岗位、知识背景、资格与积分分开呈现 |
| 学习与考试 | 前后测、评分维度、硬失败、独立核分与补学路径 |
| 任务与协作 | 任务、组队理由、职责权重、依赖与工作记录 |
| 评审与验收 | 产物、引用、退回与修订，接受指定版本并结算 |
| 成长与治理 | 积分账本、等级、系统边界与自治控制 |

桌面使用侧栏；小屏使用可折叠顶部导航和单栏卡片，不把八个入口压入底部导航。详情和弹窗尽量保留上下文，正文与主要动作不依赖悬浮才能读取。

## 3. 原型覆盖与未覆盖

### 可点击体验

- 八个 hash 导航入口与浏览器前进／后退。
- 来源说明弹窗、知识关系／来源列表切换与文本过滤。
- 资料贡献／经历访谈表单，脱敏确认校验。
- 独立核分与失败路径预览。
- 组队门禁、产物、修订与引用说明。
- 验收前核查复选框，接受后样例积分 67／33；重复接受不增加样例积分。
- 撤回影响预览、样例授权失效提示。
- 自治边界说明与样例开关。

### 不构成真实业务能力

所有页面均标识“UI 原型 · 样例数据”。刷新恢复初始样例，不保存资料、成绩、权限、任务或账本。模拟开关不启动后台运行，核分不发真实资格，验收不写真实积分，撤回不删除资料。

原型以独立视图样例展示已认证员工与待核分考核，不构成同一真实考试的连续状态机。来源弹窗为通用 FAQ 片段示例，不与每个来源按钮一一绑定；图谱为关系分组设计示意，而非真实图计算。验收、资格、撤回等跨视图状态只覆盖演示动作，不保证全部领域不变量。

当前未覆盖完整资料逐条确认、文件解析、真实身份权限、详情页实体路由、所有异常状态、评分管理、题库、运行恢复与数据持久化。这些依 PRD 实现，不能直接把原型逻辑复制成运行引擎。

## 4. 浏览器检查结果

使用 Playwright 技能在可见 Chromium 中检查：

- 八个视图 × 375、768、1024、1440px：无整页横向溢出。
- 所有视图标题可加载，未发现 pageerror。
- 验收未勾选核查时提示错误，勾选后可完成样例接受。
- 知识来源列表切换与撤回后状态提示可用。
- 原生 dialog 可用 Escape 关闭。
- 在 reduced-motion 环境下操作正常；CSS 关闭非必要动效。
- 已人工验看桌面和小屏全页截图。

原型使用语义按钮、标签、导航、aria-current、aria-pressed、状态通知、可见焦点及原生 dialog。尚未完成屏幕阅读器完整审计、全页所有颜色组合测量、200% 文字缩放与全部弹窗键盘回归，不宣称通过全面无障碍认证。

## 5. 下一阶段实现映射

UI 确认后，布局转换为 React/TypeScript 组件；真实业务状态来自 FastAPI 契约，不来自页面静态变量。来源按钮绑定实际片段和权限，资格与核分分离，撤回立即驱动后端门禁，验收与账本按单事务提交。

本阶段仅增加设计文件和说明，不修改已有项目、PRD、工作区配置或部署设施。现在停止在 UI 评审点，等待项目负责人确认。
