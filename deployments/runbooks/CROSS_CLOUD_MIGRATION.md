# 跨云迁移与回滚手册

## 适用架构

应用从阿里云入口机迁到腾讯云，域名、TLS、统一账号和 Nginx 路由仍保留在阿里云。

## 标准迁移步骤

1. 盘点服务、端口、systemd/Docker、数据目录、环境文件和定时任务。
2. 确认阿里云 Nginx 当前只代理本机环回端口。
3. 在腾讯云复制精确运行版本，不用未核验的源码重新构建替代生产镜像。
4. 在线预复制代码和数据。
5. 在腾讯云隔离启动，验证迁移脚本、健康接口和依赖。
6. 停止可能写数据的 API、Worker 和定时任务。
7. 创建最终一致性快照并记录校验值。
8. 恢复数据库、队列或文件数据。
9. 启动腾讯云应用并本机验收。
10. 建立反向 SSH 隧道。
11. 验证阿里云本机端口和公网域名。
12. 回归代表性无关产品。
13. 停止阿里云旧副本并取消自动重启。
14. 保留可恢复的旧数据一段观察期。
15. 更新 `deployments/` 文档。

## 回滚条件

出现以下任一情况应回滚：

- 腾讯云应用无法稳定启动。
- 数据校验不一致。
- 迁移脚本失败。
- 统一账号或管理员保护失效。
- 公网接口持续错误。
- 任何无关产品因为入口变更出现 404 或不可用。

## 回滚原则

1. 先停止腾讯云 Worker/API，防止继续写入。
2. 停止对应反向隧道，释放阿里云端口。
3. 确认恢复点和数据差异。
4. 仅在明确旧数据仍可作为权威数据时启动阿里云旧数据库和应用。
5. 公网与无关产品全部验收后再宣布回滚完成。

禁止两个数据库副本或两个 Worker 同时作为权威实例运行。
