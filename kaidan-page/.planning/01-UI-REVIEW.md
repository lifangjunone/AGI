# Phase 1 UI Review: 可分享的开单 MVP

**Reviewed:** 2026-09-14  
**Baseline:** Implemented React workbench, 1120x720 and 390x844 Playwright captures  
**Overall:** 18/24

| Pillar | Score | Assessment |
|--------|-------|------------|
| Copywriting | 3/4 | 行动语言直接，但示例内容与用户草稿状态不够明确，缺项反馈只出现在短暂 Toast。 |
| Visuals | 3/4 | 黑白、票据网格和荧光绿具有识别度；手机端长截图中固定行动条遮挡编辑内容。 |
| Color | 4/4 | 中性纸张色、深黑、绿色和少量珊瑚色分工清楚，对比度稳定。 |
| Typography | 3/4 | 标题与数据层级清楚，但较多 8-10px 辅助文字在手机端阅读压力偏高。 |
| Spacing | 3/4 | 桌面密度合理；手机端先展示完整预览再进入编辑，核心任务被推迟。 |
| Experience Design | 2/4 | 缺少移动端编辑/预览模式、重置确认、联系方式、可定位缺项、保存时间和错误恢复。 |

## Priority Findings

### P0 - 发布闭环不完整

- 售卖页没有卖家联系方式配置，导出页 CTA 只能打开空白邮件。
- 发布完整度没有覆盖卖家称呼、联系方式和交付周期。
- 导出失败仅展示短暂缺项文字，用户无法一键回到对应编辑步骤。

### P1 - 移动端任务顺序错误

- 390px 视口先展示约 560px 的手机预览，用户需要滚动后才能编辑。
- 固定底部行动条会遮挡表单，且在未完成服务时过早强调推广。
- 应采用“编辑 / 预览”分段切换，默认编辑，发布前再检查预览。

### P1 - 操作安全与反馈不足

- “创建新服务”会立即清空草稿，没有确认。
- Clipboard API 失败没有降级提示。
- 自动保存只有静态说明，没有最近保存状态。

### P2 - 报价预览与决策反馈不足

- 买家预览只显示主推套餐，无法比较三档价格。
- 报价编辑缺少价格梯度提示，用户可能生成倒挂套餐。
- Tab 缺少 `aria-selected` 与关联面板语义。

## Remediation Target

1. 增加联系方式、CTA 文案、交付周期并纳入发布完整度。
2. 手机端使用编辑/预览分段切换，移除遮挡表单的固定行动条。
3. 发布缺项变为持久清单，可点击跳转对应步骤。
4. 增加重置确认、保存时间、复制失败回退。
5. 预览展示三档套餐，并提示价格梯度异常。

## Post-Remediation Verification

**Result:** 23/24

- Copywriting 4/4: 发布检查、保存状态和失败反馈已改为明确行动语言。
- Visuals 4/4: 手机编辑与预览分离，固定行动条不再遮挡移动表单。
- Color 4/4: 保持原有高对比票据风格。
- Typography 3/4: 紧凑预览仍保留少量 8px 辅助文字，属于手机模型内的缩放展示。
- Spacing 4/4: 390px 与 1120x720 无横向溢出或关键操作重叠。
- Experience Design 4/4: 联系闭环、缺项定位、重置确认、价格提示、草稿迁移与错误反馈均已实现。
