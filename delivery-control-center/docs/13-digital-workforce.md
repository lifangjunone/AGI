# 数字员工与项目交付小队

## 产品边界

数字员工是企业级资产，项目交付小队是项目级实例，两者不得混用。

### 顶级模块

- 数字员工：创建、编辑、技能、工位、上岗和停用。
- 技术雷达：跨项目汇总技术情报、开源候选、CodeGraph 和许可证风险。
- 任务管理：只管理任务健康、进程、心跳、检查点和恢复。

### 项目级模块

每个 Delivery Run 保存独立的 `team.employeeIds`。首次导入需求时，系统根据岗位覆盖
和需求技能匹配自动选聘四类员工：

1. 交付指挥官
2. 技术调研员
3. 系统开发员
4. 质量验证员

用户可以在项目内替换同岗位的在岗员工。重新编组不会重置项目，只从当前检查点继续。

## 员工注册表

持久化位置：

```text
~/Library/Application Support/oneopc/settings/digital-employees.json
```

内置员工借鉴 `multica-ai/multica` 的多 Agent 分工模式，但员工定义、角色形象、调度、
恢复和项目集成为 OneOPC 自有实现，不复制其源码或视觉资产。

每名员工包含：

- 员工 ID、姓名、岗位和部门
- 职责和技能
- 数字工位
- 卡通数字人形象变体
- 在岗状态
- 来源和创建时间

## 协作轨迹

轨迹不播放预制演示数据。数据来源为：

- `run.events`：需求归档、工具选择、技术调研、阶段执行和交付事件
- `supervision.executionLedger`：重试、应用重启、检查点恢复和失败

协调器将事件映射到实际项目员工，按时间排序后生成轨迹。界面每 1.8 秒播放下一个真实
节点，支持暂停。异常恢复会作为独立节点出现，不会覆盖原执行记录。

## 安全约束

- 停用员工不参与新项目自动选聘。
- 项目小队必须覆盖四个交付岗位。
- 员工资产与 Run 记录分别持久化。
- 手动换人只追加 `team.assigned` 事件，不清空工作区。
- 界面不展示未落盘的模拟进度。
