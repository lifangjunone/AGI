# 功能清单

## 1. 优先级定义

| 标识 | 含义 |
|---|---|
| MVP | 首个可用版本必须具备，用于跑通 20 集项目 |
| P1 | 商业 Beta 需要，提升规模、效率和协作 |
| P2 | 规模化阶段能力 |

状态建议使用：待规划、设计中、开发中、待验收、已完成、已暂停。

## 23. MVP 关键用户故事

### 创建与规划

- 作为制作人，我可以上传一部小说并得到结构化故事圣经，以便快速判断改编方案。
- 作为制作人，我可以设置 20 集、每集 90 秒和总预算，让系统据此规划内容与生成方式。

### 改编与确认

- 作为编剧，我可以查看每集大纲与原文章节的对应关系，避免关键情节遗漏。
- 作为编剧，我可以锁定已确认内容，防止批量生成时被覆盖。

### 资产与一致性

- 作为美术，我可以从候选定妆图中选定角色，并让后续镜头统一引用该角色资产。
- 作为美术，我可以给角色创建新服装版本，并指定从哪一集开始生效。

### 批量生产

- 作为制作人，我可以一次启动多集镜头生成，看到任务进度、失败项、预计时间和费用。
- 作为制作人，我可以暂停项目，并在恢复后从断点继续。

### 审核与返工

- 作为审核者，我可以直接定位有问题的镜头、填写原因并进入返工队列。
- 作为剪辑，我可以替换单个镜头后仅重渲染受影响的片段。

### 交付

- 作为运营，我可以批量导出带封面、字幕、标题和简介的发布包。
- 作为项目负责人，我可以查看全项目的成片分钟数、成本和返工率。

## 24. 建议的首批开发 Epic

1. 项目、用户与存储基础；
2. 小说导入和故事知识库；
3. 改编策略、分集大纲和剧本；
4. 角色 / 场景资产与版本；
5. 分镜和镜头数据模型；
6. 模型适配层与批量任务队列；
7. 配音、图像、视频生成；
8. 自动时间线、字幕和渲染；
9. 质检、审核和局部返工；
10. 预算、用量与导出。

建议先完成一条纵向链路：**一章小说 → 一集剧本 → 三个镜头 → 配音 → 合成 → 导出**。链路稳定后再扩展到完整 20 集，而不是先把每个模块横向做全。
