# 小说到全集视频批量制作平台：产品方案

## 1. 产品概述

### 1.1 产品暂定名

**Novel Series Factory / 故事片场**

### 1.2 一句话定位

将一部长篇小说自动拆解、改编并批量生产为角色统一、剧情连续、可审核、可发布的完整视频剧集。

### 1.3 产品愿景

让内容团队像运营一条数字制片流水线一样制作系列视频：输入小说与制作要求，系统完成故事理解、剧本改编、视觉资产设计、配音、镜头生成、剪辑包装、质量检查和批量导出；人只在创意选择和关键质量节点做决策。

### 1.4 核心价值

传统 AI 视频工具通常擅长生成单张图、单个镜头或单条短片，但长篇内容生产的真正难点是：

- 全集剧情和人物关系不能前后矛盾；
- 同一人物、场景、服装和道具必须跨集保持一致；
- 数百个镜头要批量执行、失败重试并控制成本；
- 文本、画面、对白、口型、字幕和音乐要在时间轴上同步；
- 生成结果需要可审核、可局部返工，而不是整集推倒重来；
- 内容必须通过版权、敏感内容和平台规范检查。

本产品的差异化不是某个单点模型，而是围绕“长篇一致性 + 制片工作流 + 批量交付”构建的系统能力。

---

## 2. 目标用户与使用场景

### 2.1 首要用户

1. **网文版权方与小说平台**
   - 需要低成本测试大量 IP 的视频化潜力；
   - 关注批量产能、版权保护和作品级收益。

2. **短剧、漫剧和短视频工作室**
   - 有编导和运营人员，但美术、剪辑产能不足；
   - 需要稳定日更、多人协作和平台规格适配。

3. **MCN 与内容营销团队**
   - 需要将故事素材快速转为系列账号内容；
   - 关注模板复用、矩阵账号和批量发布。

4. **独立作者与小型创作团队**
   - 希望把自己的小说转成视频；
   - 关注操作简单、成本透明和成片质量。

### 2.2 暂不作为首期重点

- 高预算真人电影级制作；
- 任意时长的一键全自动成片且完全无需审核；
- 无法证明版权归属的热门小说改编；
- 复杂 3D 动画或实时游戏引擎生产。

## 3. 首期产品选择

### 3.1 建议切入形态

首期选择 **AI 漫剧 / 动态漫**，而不是直接做电影级文生视频。

推荐默认成片规格：

| 项目 | 默认规格 |
|---|---|
| 画幅 | 9:16 竖屏 |
| 单集时长 | 1–3 分钟 |
| 单部集数 | 20–100 集 |
| 单集镜头数 | 15–35 个 |
| 视觉形式 | 一致性角色图 + 镜头运动 + 局部动态 + 少量高动态视频 |
| 叙事形式 | 旁白与角色对白结合 |
| 输出 | 1080×1920 MP4、字幕文件、封面与发布文案 |

### 3.2 为什么从这一形态开始

- 对角色一致性和故事连续性的要求高，能建立真正的产品壁垒；
- 动态程度可分级，能够用成本换质量；
- 单个失败镜头可重做，不必重生成整集；
- 现有图像、视频、语音和语言模型已能支撑商业可用的 MVP；
- 生产结果适合短视频平台的连续剧消费习惯。

### 3.3 后续扩展

- 小说转有声漫；
- 小说转高动态 AI 动画；
- 小说转真人风格短剧预演；
- 剧本、漫画、播客和历史资料转系列视频；
- API 与白标制片平台。

## 4. 端到端生产流程

```text
导入小说/版权资料
        ↓
解析章节、人物、世界观、时间线
        ↓
生成“故事圣经”和改编策略
        ↓
拆分季 / 集 / 场 / 镜头
        ↓
人工审阅故事大纲与角色设定
        ↓
生成分集剧本、对白、旁白、分镜
        ↓
建立角色 / 场景 / 道具视觉资产库
        ↓
批量生成配音、画面、动作、音效和音乐
        ↓
自动剪辑、字幕、包装与混音
        ↓
自动质检 + 人工抽检 / 关键帧审核
        ↓
局部返工、版本确认
        ↓
批量导出与发布
        ↓
回收播放数据，优化后续集数
```

### 4.1 四个必须保留的人工关卡

1. **改编关卡**：确认受众、风格、主线、删改尺度和每集钩子。
2. **视觉定妆关卡**：确认主要人物、关键场景和美术风格。
3. **样集关卡**：确认第一集的节奏、声音和画面基准。
4. **发布关卡**：确认版权、敏感内容、平台规范和最终版本。

其余环节默认支持自动流转，也允许团队配置更多审批点。

## 5. 核心产品模块

### 5.1 项目与素材中心

每部小说对应一个项目，集中管理原文、授权证明、参考图、制作规格、预算、版本和成员权限。支持按作品、季和批次查看生产进度。

### 5.2 小说理解引擎

对长篇内容进行结构化解析，形成可持续更新的“故事知识库”：

- 章节摘要和关键事件；
- 人物身份、关系、动机、说话方式和成长弧；
- 世界观规则、地点、组织、能力体系；
- 故事时间线和因果链；
- 伏笔、回收点、禁改设定；
- 敏感内容、潜在侵权和改编风险。

它是后续所有生成任务的事实来源，避免每个环节各自理解原著。

### 5.3 改编与编剧工作台

用户设定受众、平台、集数、时长、节奏、风格和改编力度，系统生成：

- 全季梗概；
- 分集大纲；
- 每集开场钩子、冲突升级、高潮和结尾悬念；
- 场景剧本；
- 角色对白和旁白；
- 镜头级脚本。

所有内容都能回溯到原文章节，并标记“忠于原著”“合理补写”“重大改编”。

### 5.4 连续性与资产圣经

这是核心壁垒。系统为每个可复用对象建立唯一资产卡：

- 人物：脸型、发型、年龄、体型、服装、表情、声音、口头禅；
- 场景：空间布局、时间、天气、色调和关键物件；
- 道具：外形、持有人、状态变化；
- 视觉规则：画风、镜头语言、光影、色彩和禁用元素；
- 声音规则：角色音色、语速、情绪范围和读音词典。

生成镜头时只引用资产 ID 和状态，而不是每次从零写提示词。剧情造成的外观变化需要形成新版本，并标记生效集数。

### 5.5 分镜与导演工作台

以“集—场—镜头”三级时间线展示内容。系统自动给出景别、构图、角色调度、镜头运动、时长、对白、音效和生成方式，用户可拖拽调整并锁定满意内容。

每个镜头可选择：

- 静态图 + 运镜；
- 图生视频；
- 文生视频；
- 口型驱动；
- 素材库镜头；
- 人工上传成片。

### 5.6 多模态生成中心

通过统一的模型适配层调用不同供应商或本地模型，按镜头要求和预算自动路由。任务可以批量排队、并发执行、失败重试、暂停和续跑。

支持保留：

- 模型与版本；
- 提示词和结构化参数；
- 随机种子；
- 参考资产；
- 生成耗时与费用；
- 输出和评分；
- 父子版本关系。

### 5.7 声音制作

- 角色选角与音色锁定；
- 多角色 TTS；
- 情绪、语速、停顿和重音控制；
- 多音字、人名和专有名词词典；
- 音色克隆的授权记录；
- 背景音乐、环境音和拟音；
- 自动闪避、响度标准化和混音。

### 5.8 自动剪辑与包装

根据对白时长和分镜节奏自动组装时间线，完成镜头裁切、转场、口型同步、字幕、BGM、音效、片头片尾、角标和封面。用户可在时间线内局部调整。

### 5.9 质量控制中心

系统对每一镜、每一集和整部作品进行多层检查：

- 人脸、服装、道具与场景一致性；
- 人物数量、肢体和画面异常；
- 对白与字幕一致；
- 音画同步与口型质量；
- 黑帧、静帧、分辨率、码率和响度；
- 剧情遗漏、重复、人物越权和时间线冲突；
- 敏感内容、商标、水印和平台风险；
- 单集节奏、信息密度和结尾钩子。

低分镜头自动进入返工队列，高风险项必须人工确认。

### 5.10 批量生产控制台

以制片视角管理全集：

- 项目整体完成率；
- 各集所处阶段；
- 阻塞任务与失败原因；
- 模型队列和并发量；
- 当日生成量与成功率；
- 实际成本、预算余量和预计完工时间；
- 可批量审批、返工、替换模型和重新导出。

### 5.11 导出、发布与数据回流

按抖音、快手、视频号、B 站、YouTube 等平台生成不同画幅、码率、字幕、封面、标题和简介。首期可先导出发布包，后续连接平台账号排期发布并回收播放数据。

数据回流可用于判断：

- 哪些开场钩子留存更好；
- 哪类角色或画面更受欢迎；
- 哪一时间点流失明显；
- 后续集数是否需要调整节奏和剧情强调。

## 6. 关键产品机制

### 6.1 结构化中间产物

所有环节不直接从原文跳到视频，而是生成可编辑、可校验、可复用的中间产物：

```text
原文
→ 故事知识库
→ 季纲 / 集纲
→ 场景剧本
→ 镜头清单
→ 视觉与声音资产引用
→ 媒体素材
→ 时间线
→ 成片
```

这样可以定位错误、局部返工，也能让不同模型在统一协议下替换。

### 6.2 锁定与影响分析

用户可以锁定已确认的人物形象、台词、镜头或成片。上游内容被修改时，系统显示受影响的下游对象，用户选择是否重新生成，避免一次小改动引发全剧失控。

### 6.3 分层质量策略

不是所有镜头都使用最高成本模型：

- S 级：高潮、人物首次出场、营销切片，使用高质量视频模型；
- A 级：核心剧情镜头，使用图生视频；
- B 级：对话与过渡镜头，使用角色图、局部动态和运镜；
- C 级：回忆、信息说明和环境镜头，使用模板或素材库。

系统根据镜头重要度、运动幅度和预算推荐生成路径。

### 6.4 可复现生产

每个生成结果都记录完整配方，保证可以复做、比较和追责。模型升级时可以选取基准镜头做回归测试，不直接影响生产中的项目。

### 6.5 人机协作而非黑盒一键生成

产品默认提供“快速自动”和“专业控制”两套体验：

- 快速自动：适合独立作者，选模板后自动生成并在关键节点确认；
- 专业控制：适合工作室，开放资产、分镜、模型、预算、审核流和版本管理。

## 8. MVP 范围

### 8.1 MVP 要验证的核心假设

1. 一支 1–3 人团队能在平台内完成一部 20 集漫剧。
2. 主要角色跨 20 集保持可接受的一致性。
3. 单镜头返工不会破坏整集和上下游资产。
4. 与常规人工流程相比，交付周期和单集成本显著下降。
5. 用户愿意为稳定批量生产，而非仅为单次生成付费。

### 8.2 MVP 必做

- TXT / DOCX / EPUB 导入与章节解析；
- 故事圣经；
- 全季与分集大纲；
- 分集剧本与镜头脚本；
- 角色、场景资产卡及版本锁定；
- 角色定妆图和分镜图生成；
- 多角色 TTS 与字幕；
- 静态图运镜和图生视频两种镜头路径；
- 自动时间线和基础混音；
- 镜头级重生成与替换；
- 批量任务队列、重试和进度；
- 基础内容与技术质检；
- 预算预估、实际费用记录；
- 竖屏 MP4、字幕、封面和发布包导出。

### 8.3 MVP 暂缓

- 全自动多平台发布；
- 专业级多人实时协同；
- 数字人真人口型；
- 复杂视频局部重绘；
- 自训练角色模型；
- 市场数据自动反向改写剧情；
- 移动端完整创作。

## 9. 迭代路线图

### 阶段 0：产品与技术验证（2–4 周）

- 选取一篇有明确授权的短篇或原创故事；
- 完成 3 集、每集 60–90 秒的端到端样片；
- 对比至少两种图像模型、两种视频模型和两种 TTS；
- 测量角色一致性、单镜头成功率、人工修改时间和单集成本；
- 明确首个画风模板和质量基线。

### 阶段 1：MVP（8–12 周）

- 支持 20 集项目；
- 打通从原文到发布包的完整流程；
- 支持单人和小团队审核；
- 建立任务队列、成本控制和失败恢复；
- 邀请 3–5 个真实工作室共创。

### 阶段 2：商业 Beta（8–12 周）

- 支持 100 集项目与多项目并行；
- 增加模板市场、团队权限和审批流；
- 增加高级一致性检测和模型自动路由；
- 提供用量计费和企业账单；
- 对接 1–2 个发布平台。

### 阶段 3：规模化

- API、私有化部署和白标；
- 训练或微调作品专属模型；
- 多语言配音与全球发行；
- 数据驱动的续集优化；
- IP 资产跨作品复用与衍生内容生产。

## 10. 商业模式

### 10.1 收费建议

采用“订阅 + 生成用量 + 企业服务”的组合：

- 创作者版：月订阅，限制并发、项目数和团队人数；
- 工作室版：更高并发、批量生产、协作审批和商用授权；
- 企业版：私有模型、专属存储、API、单点登录和 SLA；
- 模型用量：按图像、视频秒数、语音字符和渲染分钟计费；
- 增值服务：模板、人工精修、版权登记和发行服务。

### 10.2 成本展示原则

生成前给出项目级预估，生成中实时显示消耗，返工前显示新增费用。允许设置：

- 项目总预算；
- 单集预算；
- 单镜头最高预算；
- 达到阈值自动暂停；
- 高成本模型的审批规则。

## 11. 成功指标

### 11.1 北极星指标

**每周通过平台完成并达到发布标准的剧集分钟数。**

该指标同时反映生成能力、工作流效率、质量和真实交付，而不会被大量无用生成任务虚增。

### 11.2 核心指标

| 维度 | 指标 |
|---|---|
| 产能 | 每人每周完成集数、从导入到首集耗时、全集交付周期 |
| 质量 | 首次通过率、镜头返工率、角色一致性评分、质检漏检率 |
| 稳定性 | 任务成功率、失败恢复率、平均排队时间 |
| 成本 | 每分钟成片成本、每个合格镜头成本、预算偏差率 |
| 使用 | 项目完成率、周活工作室数、模板复用率 |
| 商业 | 付费转化、毛利率、客户留存、每项目收入 |
| 内容效果 | 3 秒留存、完播率、追更率、互动率 |

### 11.3 MVP 建议验收线

- 20 集项目可完整跑通；
- 任务因进程中断后可以继续执行；
- 主角视觉一致性人工评分达到 4/5；
- 至少 70% 镜头首次生成后可直接使用或轻改；
- 任意单镜头可独立返工；
- 成本预估与实际偏差不超过 20%；
- 导出的成片无明显黑帧、音画错位和字幕溢出。

## 12. 风险与应对

### 12.1 版权风险

风险：用户上传未获授权小说，或生成内容过度模仿特定艺术家、演员和品牌。

应对：

- 创建项目时声明版权来源并上传授权凭证；
- 对公共领域、原创、已授权内容做不同标识；
- 保存内容来源和生成记录；
- 提供侵权投诉与下架流程；
- 禁止未经授权的真人音色与肖像克隆；
- 默认阻止明显品牌水印和受保护角色复刻。

### 12.2 长篇幻觉与剧情漂移

风险：模型遗漏前文、人物行为矛盾、伏笔错误回收。

应对：

- 使用结构化故事知识库和检索；
- 每次生成只提供相关上下文和不可违背约束；
- 对剧本运行事实一致性检查；
- 重大改编显式标注并要求确认。

### 12.3 角色一致性不足

风险：人物跨镜头变脸、换装、年龄漂移。

应对：

- 角色资产 ID、参考图组和版本锁定；
- 首次定妆必须人工审批；
- 使用多视角角色表；
- 自动人脸与服装相似度检查；
- 对关键人物启用专属适配器或微调能力。

### 12.4 成本与时延失控

风险：视频模型费用高、失败率高、排队时间不可预测。

应对：

- 先低成本预览，再高质量生成；
- 镜头分级和模型路由；
- 缓存和资产复用；
- 预算阈值、并发限制和失败熔断；
- 对失败类型选择不同重试策略，而非盲目重复。

### 12.5 平台政策与内容安全

风险：暴力、色情、未成年人、虚假信息等内容无法发布。

应对：

- 原文、剧本、画面、语音和成片多阶段审核；
- 按目标平台配置规则；
- 高风险内容进入人工审核；
- 保留审核记录和处置理由。

## 13. 技术架构建议

### 13.1 逻辑分层

```text
Web 创作端 / 管理端
        ↓
项目与工作流 API
        ↓
领域服务
├─ 小说解析与故事知识库
├─ 编剧与分镜
├─ 资产与一致性管理
├─ 媒体生成与模型路由
├─ 时间线与渲染
├─ 质量检测
└─ 计量计费与发布
        ↓
任务编排层
├─ 队列、并发、优先级
├─ 重试、幂等、断点续跑
└─ 审批等待与事件通知
        ↓
模型与基础设施层
├─ LLM / 图像 / 视频 / TTS / 音乐
├─ 对象存储 / 数据库 / 向量检索
└─ FFmpeg / GPU 渲染 / CDN
```

### 13.2 推荐核心对象

- Workspace、Member、Project；
- SourceDocument、Chapter、StoryFact；
- Character、Relationship、Location、Prop、AssetVersion；
- Season、Episode、Scene、Shot；
- ScriptVersion、StoryboardVersion、TimelineVersion；
- GenerationJob、JobAttempt、ModelProfile、PromptRecipe；
- MediaAsset、QualityCheck、ReviewTask；
- Budget、UsageRecord、Export、PublishTarget。

### 13.3 工程原则

- 工作流步骤幂等，重复执行不会产生混乱数据；
- 生成任务和业务状态分离；
- 媒体资产不可变，新结果创建新版本；
- 所有上游变更都能计算下游影响；
- 模型供应商通过统一适配器接入；
- 先保存结构化决策，再发起昂贵生成；
- 质量规则和平台规范可配置；
- 项目级数据隔离，敏感素材加密并支持删除。

## 14. 首个样片实验

建议不要一开始做 100 集。先用一篇原创或已授权、人物不超过 5 个、场景不超过 8 个的故事制作 3 集样片。

### 实验变量

- 两种美术风格；
- 静态运镜与图生视频的混合比例；
- 旁白占比；
- 单镜头平均时长；
- 高质量模型只用于 S 级镜头时的成本变化。

### 必须记录

- 每阶段耗时；
- 每镜生成次数；
- 失败原因；
- 人工修改分钟数；
- 模型费用和渲染费用；
- 一致性与观感评分；
- 观众对剧情理解和追更意愿。

实验完成后再锁定 MVP 的默认模板、质量线和定价假设。

## 15. 产品决策建议

当前最重要的不是继续扩充模型数量，而是尽快验证以下三个问题：

1. **目标客户是谁**：优先服务专业工作室，还是独立作者？
2. **首个成片标准是什么**：动态漫、有声漫，还是高动态 AI 视频？
3. **可接受的单位经济模型是什么**：每分钟成片的成本、人工时长和售价分别是多少？

建议默认选择“服务小型漫剧工作室 + 竖屏动态漫 + 20 集项目”作为 MVP 边界。它足够真实，能检验批量生产能力，又不会被电影级画面目标拖垮。
