1.

产品机制总览

数字分身的核心闭环不是“生成头像”，而是本人资料、人格建模、知识记忆、对话分发和本人纠错之间形成持续学习。

flowchart LR
    A[本人资料] --> B[人格画像]
    B --> C[知识记忆]
    C --> D[数字分身]
    D --> E[访客对话]
    E --> F[本人纠错]
    F --> B
    F --> C
    E --> G[线索 / 预约 / 转化]

3.

实时对话链路图

这张图用于讨论实时体验：音频流、VAD、检索、LLM 流式回复、TTS、Avatar 视频流，以及中途打断如何回到编排层。

sequenceDiagram
    participant User as 访客
    participant Client as 前端 Web/App
    participant RT as Realtime Gateway
    participant ASR as ASR/VAD
    participant Agent as Agent Orchestrator
    participant RAG as Memory/RAG
    participant LLM as LLM
    participant TTS as TTS
    participant Avatar as Avatar Engine

    User->>Client: 说话/输入问题
    Client->>RT: 音频流 / 文本流
    RT->>ASR: 推送音频 chunk
    ASR->>ASR: VAD 判断是否说完
    ASR->>Agent: 转写文本 + 语音状态
    Agent->>Agent: 判断意图和风险
    Agent->>RAG: 检索本人资料/历史记忆
    RAG-->>Agent: 返回相关内容和来源
    Agent->>LLM: system persona + context + user query
    LLM-->>Agent: 流式生成回复
    Agent->>TTS: 流式文本转语音
    TTS-->>Avatar: 音频 chunk
    Avatar-->>RT: 视频帧/音频流
    RT-->>Client: WebRTC 返回
    Client-->>User: 数字分身回答
    User->>Client: 中途打断
    Client->>RT: barge-in 信号
    RT->>Agent: 停止当前输出
    Agent->>LLM: 重新组织上下文
< 1s首次文字响应
< 1.5s语音首包
< 2.5s视频首帧
2-4s端到端回答
< 500ms中途打断响应
可审计关键对话和工具调用

5.

创建分身流程

这张图用于解释从创建到发布的产品流程。关键节点是“本人确认像不像”：不像就进入纠错与重训，通过才设置权限并发布。

flowchart TD
    A[开始创建] --> B[身份与授权]
    B --> C[上传本人资料]
    C --> D[自动生成人格画像]
    D --> E[训练知识记忆]
    E --> F[选择声音方案]
    F --> G[选择形象方案]
    G --> H[试聊 20 题]
    H --> I{本人确认像不像}
    I -- 通过 --> K[设置权限边界]
    K --> L[发布到渠道]
    I -- 不像 --> J[纠错与重训]
    J --> H
