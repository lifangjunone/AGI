# MeYou 产品调研与优化跟踪

本地代码与真实运行是证据来源；不以 README 的能力描述作为完成证明。

## 2026-10-29 首轮调研

| 问题 | 当前证据 | 优先级与处理 |

## 验证原则

- 不改变真实账号额度、模型密钥、套餐与生产配置。
- 不启动持续自治制造热闹；调研以读取和本地 UI 路径为主。
- 使用 ui-ux-pro-max 的深链接、状态反馈与渐进展开建议；保留原创温暖街区。
- 修复后验证浏览器刷新/后退、草稿保持、消息过滤、移动面板关闭及可见错误。
- 外部参考录屏只证明可观察的呈现，不证明其后台真实行为。

## 第二批：历史消息可读性与完整性

- 调研发现快照最多返回120条，不能支持完整历史检索。新增 `/api/v1/plaza/history`，圈子权限先检查，游标按数据库原始时间戳和ID排序；限定每页1–100条，默认40条。
- 支持姓名/Agent名称/正文服务端检索及线程过滤；搜索中的 `%` 和 `_` 当作字面字符处理，不作为通配符。不可访问圈子返回403，非法及跨圈游标返回400。
- 折叠式阅读面板新增“加载更早消息”、加载状态和错误重试；保留当前可见消息，查询切换时取消旧请求，避免结果串线。
- 使用真实林汐账号只读取现有记录，验证两页ID无重复、姓名结果匹配、非法游标拒绝、无权限目标拒绝，浏览器分页从40条扩展到80条；未发布聊天、未修改运行配置。
- 验证脚本 `/tmp/playwright-test-meyou-history.js`；截图 `/tmp/meyou-history-search.png`。服务端权限/游标测试覆盖4项，前端增加失败保留与重试测试。
- 已实现历史消息分页；完整话题目录仍只来自近期快照，旧线程可以用接口ID检索，但面板尚没有全部话题目录。私密圈子的真实成员/非成员组合还需独立集成验收。
- 全站双语、圈子规模化查询、模型/任务生命周期以及企业接待仍属于后续优化，不据此宣布产品总体完成。

## 第三批：历史话题与私密圈子验收

- 阅读面板按需获取话题目录，提供“加载更早话题”及失败重试；选旧话题后消息、完整标题与讨论状态同步。保持默认折叠，不增加地图浮层。
- 使用现有三个独立验收账号创建一组临时数据库私密圈子与测试记录：圈主、成员通过，非成员403，未登录401；消息和话题接口均验证。测试完按精确 UUID/handle 删除临时 community，并级联移除这组数据；没有删除或改动已有圈子与账户。
- 真实公开圈子话题两页无重复，浏览器话题目录扩展到60条以上并选择早期讨论，完整标题、3种状态来源和历史消息可读；截图 `/tmp/meyou-historical-topics.png`。

## 第四批：模型执行与个人回复安全边界

- 调研发现模型开关仅在请求前检查，在途请求可能继续发布；消息来源写死为 Ark/环境模型名，与管理端实际配置不一致。模型执行现在携带实际供应商、模型名和配置版本，请求返回后及发布前重新校验；管理端停用或修改配置后拒绝旧结果。空回复视为失败。不会把密钥或配置指纹写入公开消息元数据。
- 个人回复在模型返回后重新读取 Agent 和会话权限；暂停、拉黑、待真人状态不发送，自动授权改为确认时只生成草稿。
- 个人模型输出新增付款/合同/退款/承诺关键词安全检查，高风险内容保留待确认草稿并升级真人，不自动发送。此检查是保守规则，不等价于完整内容安全检测或隐私泄漏防护。
- 模型边界5项与个人回复发布边界5项为隔离契约测试，包含在途禁用/配置变更、实际来源、空结果、待真人切换、回复前确认和输出升级；未修改真实管理端配置以模拟开关，也不声称完成生产开关端到端验收。
- 共享7项、API55项、前端24项测试通过，全工作区类型检查和构建通过；主包仍存在500kB警告。
- 阅读面板以真实圈子只读验证默认收起、上拉打开、Esc焦点返回、草稿保留、刷新收起和消息区不被输入栏遮挡，未发布测试草稿。脚本 `/tmp/playwright-test-meyou-feed-dock.cjs`。
- 剩余风险：配置校验与数据库发布并非同一原子事务；管理端停用不会取消供应商已经收到的网络请求。自动回复输入已持久化后模型失败的重试/消息送达反馈、并发幂等、个人回复调用配额预留及更完整的输出安全仍须继续完善。

## 第五批：真人送达与 Agent 回复分离

- 调研发现真人消息先写数据库，模型失败后整个接口却返回503，前端保留输入并显示发送失败，容易诱发重复发送。
- 消息落库后立即发送通知；模型错误转换为独立 `agent.status=unavailable` 和安全原因码，接口保持201及 `delivery=delivered`。审计故障也不能改变已送达结果，不暴露供应商连接细节。
- 消息插入与会话更新时间改为同一数据库事务，防止第二步失败留下半完成写入。
- 前端区分送达、等待确认、等待真人、模型停用与回复不可用；已发送文本清空，等待期间新写草稿不被旧请求清空。新增中英文状态文案，明确不重复发送。
- API4项结果封装测试、1项HTTP路由契约测试及前端3项文案测试、1项发送界面测试通过；依赖隔离测试不等价于真实数据库故障注入、真实模型或浏览器端到端验收。
- 剩余：接口仍同步等模型返回才给发送端响应；网络断线情况下需要客户端幂等键及持久化回复任务，不能据此宣称完成可靠消息投递。全站双语、大规模地图和企业闭环继续保留在总体待验收范围。

## 第六批：实时通知访问隔离

- 调研确认原 WebSocket 无登录校验，所有连接会收到私聊ID、消息ID和关系提案元数据。新增登录握手与Origin校验，广播按数据库真实所有者/参与者确定受众；不能通过传入recipientId扩展通知权限。
- 私聊通知仅双方接收；私密圈子仅当前成员和圈主接收；关系提案仅发起者与目标用户接收。未关联圈子的presence只通知本人，未知/不存在/查询失败的事件拒绝广播。
- 每次敏感事件发送前重新校验会话身份，过期或退出登录的连接关闭；没有缓存成员权限。此方式会增加身份查询开销，需要后续负载测试及安全的失效缓存方案。
- WebSocket路由原注册顺序未等插件就绪，合法injectWS握手挂起。将路由放入插件之后的注册作用域，验证真实协议握手可完成。
- 受众5项测试、WebSocket4项测试通过，其中三个隔离测试身份同时连接，双方收到私聊通知、第三方没有收到；匿名401、跨站403、合法升级通过。身份与数据库依赖为测试替身，协议传输真实；不是生产多用户端到端验收。
- 剩余：实时增量游标只是时间戳，不是持久事件序列，断线仍靠REST轮询；未完成完整可靠补偿、大规模连接压测或企业客户房间订阅。总体目标保持进行中。

## 第七批：联系人资料与草稿确认

- 联系人接口此前返回完整users行，含LifeYouMe账号ID、套餐、风险状态和时间戳。消息列表及详情改用公开字段白名单；新加数据库字段不会默认暴露给联系人。没有发现此处读取密码表，但不以此为由保留无必要的内部字段。
- 草稿确认此前只查草稿所有者，没有绑定URL会话ID；连续并发确认可能写入两条消息，拉黑后也未检查。现在绑定会话与所有者，事务内锁定草稿，校验参与者与双向拉黑，消息和草稿状态同一事务提交。
- 空编辑返回400，不再悄悄使用旧正文；已处理/错误会话草稿拒绝；拉黑返回403，仍允许丢弃草稿。
- 公开字段2项、草稿事务5项隔离测试通过。真实开发数据库使用现有独立“验收·”账号创建临时会话，验证错误会话拒绝、两请求并发仅一条消息。结束后按精确UUID删除该临时会话及级联草稿消息，没有改动现有账号或会话。脚本 `/tmp/meyou-draft-concurrency.mjs`。
- 剩余：与同时新建拉黑记录之间仍有竞态窗口，需要统一联系权限锁协议；客户端断线重试幂等、持久化任务、权限分层和企业工作流继续验收，不声明全产品完成。

## 第八批：客户线程管理闭环

- 调研发现企业customer_thread列表行无点击处理，知识库入口为规划中，企业公开页面与自动接待未闭环。本轮接上线程详情、接管、内部备注、优先级、解决和重新打开；不将状态变更描述为模型回答。
- 新增GET/PATCH `/api/v1/customers/:id`，按organizations.owner_id校验当前管理员；UUID和更新内容验证，错误组织返回404。线程更新、负责人和审计同一事务，行锁串行写入防止备注覆盖。
- 客户行区分公开留言与企业线程路由；详情有加载、失败重试、保存反馈与草稿保留，中英文系统文案。明确内部备注不发送给客户，客户回复及知识库尚未接入，不提供无效“恢复Agent”按钮。
- API4项、前端1项隔离测试通过；真实开发数据库独立验收账号创建临时企业/线程，跨组织拒绝，接管/备注/高优先级/解决/重新打开以及3条审计均验证。精确清理临时企业、线程及验收审计，保留原数据；脚本 `/tmp/meyou-customer-lifecycle.mjs`。

- 权限或启停变化与审计记录在同一事务中提交；删除先锁定本人记录，再删除正文并写入不包含正文的删除审计。首版不允许编辑系统生成的记忆正文或来源，避免把真实事件来源改写成不可审计内容；仅返回归一化来源类型，不暴露内部事件关联字符串。
- “我的 Agent”新增独立“记忆与权限”区域，不阻塞原五步配置。每条记忆默认折叠，展开后才显示正文、使用范围、暂停/恢复及永久删除；删除使用独立二次确认，取消按钮获得初始焦点。权限变更即时保存并通过 `role=status` 反馈，选择框具备稳定可访问名称。设计采用 `ui-ux-pro-max` 的渐进披露、危险操作确认和明确反馈建议。
- 新增3项服务端所有权/事务契约和1项前端折叠/权限/删除契约。最终API188项、Web66项全部通过，全部工作区类型检查和生产构建通过；前端主包约566kB的既有分包警告继续保留。
- 真实开发数据库和浏览器使用两名不可发现的隔离账号、12条标记记忆：首屏10条、加载更早后12条；权限修改为公开、暂停、刷新持久化、恢复、删除二次确认、刷新后消失、数据库删除及更新/删除审计全部通过。第二账号修改第一账号记录返回404且数据库未变。脚本 `/tmp/playwright-test-meyou-memory.cjs`；多轮脚本收敛中发现审计外键不级联，最终按确切fixture账号先删对应审计再删用户，确认用户与相关审计残留均为0。没有调用模型、修改现有账号或额度。
