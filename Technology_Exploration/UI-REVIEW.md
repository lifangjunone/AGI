# Technology Exploration 产品与 UI 审查

审查范围：数据源、排序质量、信息架构、视觉设计、交互体验和用户闭环。

## 结论

产品已从“多平台热榜查看器”升级为以结论和验证动作为核心的技术信号工作台。第二轮改造统一了原生工具栏与 WebView 的导航层级，强化 30 秒速读和知识卡阅读路径，并补齐多屏启动、键盘焦点和响应式体验。下一阶段应继续建设收藏、主题关注和事件长期追踪。

|---|---:|---|

总分：21/24（第一轮审查为 13/24）。

## 数据源审查

### 已有优势

- 17 个有效采集源，覆盖国内内容平台、开发者社区、论文、海外新闻、视频与社交平台。
- 单来源失败不会阻塞整份报告，并能展示来源健康状态。
- 无密钥模式可以直接运行，降低首次使用门槛。

### 高优先级问题

1. 数据质量缺少统一门禁。
   - 230 条榜单项中有 87 条摘要不足 10 个字符。
   - 32 条标题超过 120 字，部分标题直接包含完整 URL。
   - `AI今日热榜` 出现“结果”这类无意义标题。
   - `6551 AI` 混入港股行情，`6551 加密` 混入战争和石油新闻。

2. 排序分数不可比较。
   - 不同平台的互动量口径差异巨大，却直接进入同一对数公式。
   - 40 条内容得分达到 100，分数严重饱和。
   - 缺少来源可信度、跨源共识、增长速度和主题匹配度。

3. 去重只处理完全一致的规范化标题。
   - 同一事件换一种标题后仍会重复出现。
   - 当前已存在跨分类完全重复内容。
   - 缺少实体抽取、语义相似度和事件级聚类。

4. 采集可靠性不足。
   - HTTP 客户端没有重试、指数退避、缓存、ETag 或限流控制。
   - 多个来源依赖 HTML 正则解析，页面结构变化后容易静默降质。
   - 仅记录“成功条数”，没有新鲜度、字段完整度和异常比例。

## UX 与产品问题

### 核心定位

目前首屏同时服务泛热点阅读、AI 技术发现和加密资讯，目标用户不明确。建议将默认体验收敛为：

> 每天用 10 分钟发现值得跟进的技术、产品和行业变化，并说明为什么值得关注。

泛娱乐榜单可以作为可选频道，而不是默认首屏主体。

### 缺失的用户闭环

- 收藏与稍后读。
- 标记已读和隐藏不感兴趣。
- 关注主题、公司、人物或产品。
- 同一事件的后续更新和时间线。
- “为什么推荐给我”的解释。
- 一键生成摘要、对比、研究任务或飞书推送。
- 历史趋势：首次出现、持续升温、跨平台扩散、热度回落。

## UI 问题

1. 响应式失效。
   - 约 736px 可用宽度时，顶部模式按钮和左侧分类逐字换行。
   - 右侧来源状态直接消失。
   - 原生窗口允许缩至 860px，但页面在该范围没有稳定布局。

2. 页面结构过长。
   - 23 张榜单卡同时展开，窄视口总高度超过 12,000px。
   - 用户无法快速形成“今天最重要的三件事”的认知。

3. 卡片视觉差异不足。
   - 所有平台几乎只有首字母变化。
   - 缺少平台图标、事件封面、趋势曲线和信息类型标记。

4. 自定义能力重于决策能力。
   - 用户可以调颜色、尺寸和排版，却不能收藏、屏蔽或订阅。
   - 应优先投资高频工作流，再扩展装饰性配置。

## 推荐路线图

### P0：可信数据层

- 建立字段校验和质量分，过滤无意义、超长、含裸 URL 的标题。
- 使用平台内百分位归一化热度，避免不同平台互动量直接比较。
- 增加来源可信度、跨源数量、速度和新鲜度四个可解释维度。
- 使用标题向量与实体规则进行事件聚类，合并同一事件。
- 为采集器增加重试、退避、缓存和结构异常告警。

验收指标：

- 无意义标题比例低于 1%。
- 裸 URL 标题为 0。
- 摘要完整率超过 95%。
- Top 20 人工相关性超过 85%。
- 同事件重复率低于 5%。

### P1：重新设计默认首页

- 第一屏展示“今日 5 个关键信号”，不是 23 个平台入口。
- 每个信号展示：发生了什么、为什么重要、跨平台证据、可能影响。
- 平台榜单下沉到“探索”页。
- 增加“技术 / 产品 / 商业 / 研究 / 泛热点”频道。
- 修复 860-1180px 窗口响应式，禁止文字逐字换行。

### P1：用户行动闭环

- 收藏、已读、隐藏、主题关注。
- 事件详情页与更新历史。
- 一键加入每日简报和飞书推送。
- 根据行为调整推荐，而不是只保存视觉布局。

### P2：视觉品牌升级

- 使用真实平台图标和一致的图标系统。
- 用趋势、共识和可信度颜色表达数据语义。
- 为重点事件加入真实媒体图或产品截图。
- 将自定义主题收敛为少数高质量预设，降低配置负担。

## 建议的下一版本

下一版本建议命名为“信号工作台”，目标不是增加更多来源，而是完成一条纵向闭环：

`多源采集 -> 质量清洗 -> 事件聚类 -> 今日关键信号 -> 收藏/关注 -> 后续更新 -> 飞书简报`

这是当前产品从“能看”升级到“每天值得打开”的关键。

- 禁止恢复旧窗口位置，并让窗口跟随鼠标所在显示器居中，解决多屏启动后找不到窗口。

## 第三轮原生桌面化改造

用户反馈第二轮仍像 Web 页面。复审确认问题来自横向导航重复、连续卡片长页和缺少桌面主从分栏，而不是单纯配色。

已完成：

- 情报工作台改为 macOS 三栏结构：Source List、信号列表、知识详情。
- 今日信号默认先展示全宽网格总览；点击具体信号后才进入列表与详情阅读，并支持一键返回总览。
- 原生标题栏承载全局模式、报告目录、设置和刷新，Web 内容不再重复品牌顶栏。
- 关注主题进入左侧 Source List，采用稳定选中态和语义色圆点，不再使用横向胶囊堆叠。
- 今日信号改为紧凑列表；只在右侧展示当前信号详情，避免连续大卡片和整页滚动。
- 列表与详情独立滚动，窗口整体固定；主题筛选、搜索和已掌握筛选会自动选择首条有效信号。
- 探索榜单和技术雷达继续使用同一左侧资料库切换。
- 项目需求中心同步使用 Source List 材质、固定窗口和内容区局部滚动。
