# 消息灵宠 MVP

一个“桌面宠物 + 多平台消息中心 + 紧急待办 + 每日总结”的可运行原型。

## 当前能力

- 区分飞书/微信、个人私聊/群聊。
- 支持配置重要联系人和重要群。
- 将群聊 `@我`、重要联系人、重要群、紧急语义进行优先级排序。
- 从任务型消息中提取待办和可能的截止时间。
- 用宠物状态、醒目卡片和独立入口突出关键消息。
- 支持消息筛选、标记已处理、待办完成和本地状态保存。
- 提供可替换的消息处理引擎，当前数据为本地演示数据。

## MVP 边界与真实接入

当前版本不会读取用户真实微信或飞书内容。接入真实消息时建议按平台分别处理：

- 飞书：自建应用 + 事件订阅，可合法获取授权范围内的私聊、群消息及 `@机器人` 事件。
- 企业微信：通过自建应用、会话内容存档等企业能力接入。
- 个人微信：没有稳定、公开的全量消息 API，不建议使用注入或非官方 Hook。桌面 MVP 可先采用“系统通知采集 + 点击跳转”，内容能力受操作系统通知权限限制。
- 其他平台：通过统一适配器输出标准消息结构，再交给 `src/message-engine.mjs` 分类。

## 飞书事件接入

服务已提供：

```text
POST /api/integrations/feishu/events
```

准备工作：

1. 在飞书开放平台创建企业自建应用。
2. 订阅 `im.message.receive_v1` 消息接收事件，并为应用开通所需消息权限。
3. 复制事件订阅页面的 Verification Token，启动前设置为
   `FEISHU_VERIFICATION_TOKEN`。
4. 将自己的 Open ID 设置为 `FEISHU_CURRENT_USER_OPEN_ID`，否则系统不会把
   任意群成员的 mention 误判为 `@我`。
5. 飞书要求公网可访问的 HTTPS 回调地址。本地开发时需要使用可信的 HTTPS
   隧道，将公网地址转发到本应用的本地端口，再把完整事件地址填写到飞书后台。

示例：

```bash
FEISHU_VERIFICATION_TOKEN=\"你的令牌\" \
FEISHU_CURRENT_USER_OPEN_ID=\"你的OpenID\" \
npm run desktop
```

应用只在响应中返回“是否已配置”，不会把令牌或 Open ID 发给浏览器。接收到的
消息与规则保存在本机应用数据目录中；独立 Web 模式默认保存在项目的 `.data`
目录，该目录已被仓库全局规则忽略。

## Chrome 浏览器伴侣

商店中的旧扩展已不可用，因此项目内置了独立的 Manifest V3 扩展：

```text
/Users/bytedance/Desktop/agi/message-pet-mvp/browser-extension
```

本地安装：

1. 打开 `chrome://extensions`。
2. 开启右上角“开发者模式”。
3. 点击“加载已解压的扩展程序”，选择上面的 `browser-extension` 目录。
4. 在消息灵宠中进入“规则与接入”，复制浏览器伴侣配对码。
5. 点击 Chrome 工具栏中的消息灵宠图标，粘贴配对码并测试连接。

当前扩展只做两类采集：

- 捕获飞书网页版、Lark 网页版和微信网页版主动创建的浏览器通知。
- 用户在网页中选中文字后，通过右键菜单主动发送到消息灵宠。

它不会扫描全部页面 DOM、读取历史聊天记录或获取登录凭证。消息只提交至
`127.0.0.1:43173`，并且必须携带桌面应用随机生成的本机配对码。
