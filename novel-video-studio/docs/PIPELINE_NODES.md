# 固定流水线与节点产物

## 来源确认门禁

创建任务后，系统只执行 `NODE 01 全网检索`。检索结果会停在 `source-review`，不会读取正文或调用后续生成模型。

候选来源包含：

- 作品名、作者、出版年份与语言
- Project Gutenberg、Open Library、Google Books 或公版目录来源
- 标题匹配度与版权状态
- 全文、内容梗概或仅元数据标记
- 可打开核验的原始来源链接

`NODE 01` 同时保存逐源检索轨迹：

- 检索源名称与类型
- 实际查询 URL
- `completed / degraded / failed / skipped` 状态
- 候选命中数与耗时
- WAF、限流、超时或未配置凭据等错误

国内检索默认执行 360 全网查询，并对 `config/novel-sources.json` 中的每个启用域名单独执行站内查询。默认注册表包含 23 个已核验来源，覆盖中文网文、公版名著、海外原创和数字图书馆；站点可在应用内增删或停用，结果持久化到数据目录的 `search-sources.json`。精确目录候选在上游搜索受限时仍可降级命中。

来源注册表还记录免费模式、注册要求、网页阅读、下载格式、广告、版权说明、自动化策略和核验时间。`cn-qidianzww.com.cn` 等仿冒域名及未通过正版来源核验的域名由服务端拒绝。完整核验结果见 [`FREE_NOVEL_SOURCES.md`](FREE_NOVEL_SOURCES.md)。

用户确认具体来源后，任务重新进入生产队列，从 `NODE 02 内容核验` 继续。如果所选来源没有可处理版权，任务进入 `rights-review`，可返回来源库重新选择。

对于起点等商业作品，系统不绕过站点访问控制抓取正文。用户可选择已核验版本后导入拥有处理权的 TXT/Markdown 全文；原文单独保存在 `data/imports/<project-id>/`，项目状态只保存文件名、字数、字节数、SHA-256、版权声明和前 2,000 字预览。导入完成后来源标记为 `user-provided`，自动恢复 `NODE 02`。

## 六个固定节点

| Node | 名称 | 输入 | 主要产物 |
| --- | --- | --- | --- |
| 01 | 全网检索 | 小说名、检索策略、来源配置 | 逐源查询轨迹、候选版本、推荐来源、作者、版权、匹配度 |
| 02 | 内容核验 | 已确认来源或授权导入文件 | 正文字数、内容预览、SHA-256、版权结果、降级方式 |
| 03 | 全季编剧 | 正文或梗概、本季集数、每集五分钟规格 | 全季总纲、全部分集剧本、每集 10 段连续分镜 |
| 04 | 连续性设定 | 全季角色、服装、道具、地点与时间线 | 稳定连续性 ID、视觉资产、跨集状态 |
| 05 | 分集渲染 | 锁定后的全季内容、片段计划、上一段尾帧 | 顺序生成的 30 秒片段、任务状态、本地视频和尾帧 |
| 06 | 逐集装配 | 当前集 10 个片段、五分钟目标、编码器 | 各集独立 MP4、完成集数和全季交付状态 |

生产模式下，`NODE 03` 默认记录并调用规划模型 `glm-5-2-260617`，`NODE 05` 默认记录并调用 Seedance 2.5 模型 `doubao-seedance-2-5-260628`。两者均可通过服务端环境变量覆盖。

系统必须先完成并持久化本季所有分集内容，才能进入 `NODE 05`。每集固定 300 秒，拆成 10 个 30 秒片段；同一项目内只允许一个片段在远端执行。片段成功后立即下载视频和尾帧，下一片段以该尾帧作为首帧；新一集首段承接上一集末段尾帧。当前集装配完成后才会启动下一集。

每个节点持久化：

- `status`: `pending / running / completed / paused / failed`
- `startedAt` 与 `completedAt`
- 结构化 `input`
- 结构化 `output`
- 节点错误 `error`

生产总览中的六个节点均可点击。历史任务会优先读取持久化节点记录；旧任务没有节点记录时，根据已有来源、剧本、资产、镜头和成片数据生成只读摘要。
