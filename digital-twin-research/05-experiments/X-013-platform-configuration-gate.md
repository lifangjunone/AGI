# X-013 专家分身平台配置门禁

日期：2026-11-09
状态：休眠；只有 X-012A 与 X-012B 均通过后才允许启动

## 目的

验证 X-012A/B 均通过后的差异能否被现有专家分身平台或开源组合低成本复制。X-013 不是寻找更多功能，而是阻止把可配置能力误建成独立 SaaS。

## 前置条件

以下条件全部满足前不得联系厂商、购买高阶方案或开发连接器：

1. X-012A 完成 3 名专家、240 名参与者和真实支付，并通过汇总身份付费主效应。
2. X-012B 使用新参与者完成足额功效的留存与跨专家确认。
3. 至少两名专家分别达到预先规定的方向与经济门槛。
4. 稳态贡献毛利完整计入退款、税费、支付费、专家分成、获客、复核和支持成本。

若 X-012A 只证明签认价值，或 X-012B 未确认留存与跨专家价值，X-013 取消。

## 候选

1. Delphi。
2. Coachvox。
3. BuddyPro。
4. 开源组合：现有随机化脚本 + PostgreSQL/pgvector + Langfuse + Stripe。

可增加平台，但不得删除上述基线，也不得只比较营销页面。

## 统一测试案例

使用一个已授权、脱敏的专家资料快照和四名内部测试参与者。每个方案必须完成：

1. 从同一知识快照生成 A/B/C/D。
2. 只改变身份展示与签认门禁，不改变模型、提示、检索或内容。
3. 参与者只能看到自己的变体，匿名组不能从 URL、域名、发件人、发票、来源标签或页面代码推断专家姓名。
4. C/D 在发布前进入同一专家的盲审队列。
5. 复核界面不显示 arm、既往关系、支付状态或姓名展示条件。
6. 保存生成原稿、专家修改 diff、签认、来源、模型和知识版本。
7. 使用同一真实价格完成支付、退款和事件导出。
8. 导出参与者级曝光、支付、使用、复核、退款和成本记录。
9. 撤回一份专家资料并证明后续回答不再引用它。
10. 删除一名测试参与者的非财务数据并保留删除审计。

## 强制门禁

以下六项缺一即失败：

- 同一知识快照。
- 匿名组无身份泄漏。
- C/D 同一专家且复核盲法成立。
- 原稿、diff、签认和版本可审计。
- 真实支付、退款和参与者级事件可导出。
- 资料撤回与参与者删除可验证。

“可通过定制 API 开发”不算平台原生支持，开发时间和代码量必须计入配置成本。

## 成本口径

统一记录：

- 首次可用所需工程人日。
- 平台订阅、API、模型、存储、支付和顾问费用。
- 每 100 名付费用户的固定与变动成本。
- 专家每 100 次复核的分钟数。
- 维护、升级、导出和退出成本。
- 需要平台方人工介入的步骤。

现有方案判定为可替代，必须同时满足：

1. 全部强制门禁通过。
2. 首次配置不超过 20 个工程人日。
3. 首年软件成本不超过 10,000 美元。
4. 不要求改变 X-012 已证明的价值机制。
5. 数据可导出，不把专家和参与者锁死在单一平台。

## 产品启动门禁

独立产品只有同时满足以下条件才允许定义：

1. X-012 证明身份与签认至少一个组合产生可重复经济价值，且身份价值不能完全由签认解释。
2. X-013 中没有任何现有方案在成本上限内通过全部强制门禁。
3. 至少 3 名专家给出包含预算范围和决策日期的书面信号，或 1 名专家为固定范围试点真实付款。
4. 产品对象明确为跨平台的专家保证与审计层，而不是新的聊天、知识库、支付或 Avatar 平台。
5. 90 天试点能测量付费转化、重复使用、复核分钟、退款、纠错和毛利。

任一条件缺失时，默认选择配置现有平台、提供一次性服务或停止。

## 停止条件

- 任一现有平台在成本上限内完成全部强制门禁。
- X-012 效应只来自既有粉丝或课程捆绑。
- 专家不愿为签认与审计单独承担时间或付费。
- 输出质量必须依赖每次人工重写，无法形成正毛利。
- 数据授权、匿名组或删除要求无法合规完成。
